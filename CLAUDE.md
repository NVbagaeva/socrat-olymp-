# CLAUDE.md

Сайт — Next.js со статическим экспортом в `app/` (`output: 'export'`,
`trailingSlash: true`), хостинг — Apache (`app/public/.htaccess`).

## Перед работой: посмотреть, кто уже в этой области

Над сайтом одновременно работает несколько сессий, и каждая не видит
остальных. Поэтому **до первой правки** посмотри, не делает ли кто-то
то же самое:

```bash
gh pr list --state open --limit 40
git branch -r --sort=-committerdate | head -20
```

Нашёл открытый PR или свежую ветку по своей области — прочитай, что там
уже сделано, и либо продолжи ту работу, либо возьми часть, которой в ней
нет, и скажи об этом в описании своего PR. Не начинай второй раз то, что
уже лежит в чужой ветке.

Если твоя правка трогает файл из чужого открытого PR — проверь заранее,
сойдутся ли ветки:

```bash
git merge --no-commit --no-ff origin/<чужая-ветка> && git merge --abort
```

Цена пропуска этого шага уже известна: один и тот же класс `.kz`
переименовали в трёх ветках подряд, и шесть PR подряд строили выдачу ДЗ
на поколении, которое к тому времени заменили.

## Один класс CSS — один смысл

Сайт собирается в общий CSS, и стили посещённой страницы остаются
загруженными после перехода внутри сайта. Если два несвязанных
компонента объявили один класс с раскладкой, правила одного лягут на
разметку другого. Так `.kz` картинки к задаче (`float: right`) сжимал
карту «О задании» в полоску у правого края.

Новому компоненту — свой префикс, а не короткое общее слово
(`kzad-`, `snimok-okno-`). Проверка: `pnpm test:css-klassy`.

## Перенос и переименование страниц

- Перенёс или переименовал страницу — **сразу** обнови все внутренние
  ссылки на новый адрес: меню, вкладки, карточки, оглавления, данные
  задач, пропсы вроде `listHref`, адреса, собираемые в коде. Хвосты
  адресов бери из общих констант (`content/opornye.ts` → `OPORNYE.tail`,
  `lib/paths.ts`), а не пиши строкой.
- Адрес раздела банка профиля — по коду (`/zadaniya/uravneniya/`), не
  по номеру: собирай его через `href(ZADANIYA, номер, …)` или
  `razdelBase(номер)` из `lib/paths.ts`, цифру раздела в адрес не пиши.
  Прежние адреса по номеру — таблица `content/pereezd/starye-adresa.json`
  и блок 301 (`pnpm build:pereezd`, проверка `pnpm test:pereezd`).
- Заглушки «Страница переехала» (`components/layout/Redirect.tsx`,
  `RedirectPage`) — только для старых внешних ссылок и закладок.
  Внутри сайта на них не ссылаться никогда.
- Каждой заглушке — серверный 301 в `app/public/.htaccess` (раздел
  «Переехавшие страницы») на тот же адрес, что у неё самой.
- Перед коммитом собрать сайт и запустить проверку ссылок:

  ```bash
  cd app && LEGAL_DRAFT=1 pnpm build && pnpm test:links
  ```

  `scripts/check-links.mjs` падает, если внутренняя ссылка ведёт на
  заглушку или в 404, если у заглушки нет 301 в `.htaccess` или её новый
  адрес не существует. Список проблем должен быть пустым.
