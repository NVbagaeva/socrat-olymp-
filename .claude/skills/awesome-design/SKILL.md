# awesome-design — дизайн-системы реальных сайтов

Папка `references/` содержит по одному файлу на сайт: `references/<сайт>.md`.
Каждый файл — DESIGN.md из проекта
[VoltAgent/awesome-design-md](https://github.com/VoltAgent/awesome-design-md):
восстановленная по живому сайту дизайн-система в YAML-подобной форме —
палитра, шкала шрифтов, отступы, радиусы, тени, компоненты (кнопки, карточки,
поля, навигация), правила «делать / не делать» и тон голоса.

## Когда использовать

- Нужен цельный «премиальный» стиль, а не набор случайных решений.
- Нужен ориентир по палитре, шрифтовой шкале или ритму отступов.
- Делается редизайн и нужен внятный референс «как у взрослых продуктов».

## Как использовать

1. Определить задачу: образовательный продукт, SaaS-панель, лендинг, документация.
2. Выбрать **1–2** файла, не больше — прочитать их целиком и работать от них.
   Чтение всей папки запрещено: это 70+ файлов по 20–40 КБ.
3. Из файла брать: цвета (как систему — фон, текст, акцент, границы, состояния),
   шрифты и шкалу размеров, отступы и радиусы, принципы компоновки и иерархии,
   правила состояний (hover, focus, disabled).
4. **Не брать**: логотипы, названия брендов, фирменные слоганы, уникальные
   иллюстрации и любые элементы, по которым продукт узнаётся как чужой.
   Результат должен быть «в духе», а не копией.
5. Если в проекте уже есть собственная палитра и токены (как в этом репозитории:
   `app/src/styles/tokens.css`), референс только подсказывает решения —
   значения остаются в токенах проекта, новые хексы в компонентах не появляются.
