## 2. Что не так с точки зрения продукта

1. **Ответы в открытом виде.** `const ANS = {...}` и `VAR[n][i].a` — любой ученик открывает «Просмотр кода» и видит все 224 ответа. Кнопка «Показать ответ» честно фиксирует `seen`, но обходится за 10 секунд.
2. **Вся база в одном файле.** 224 задачи + чертежи + теория выгружаются одним `Ctrl+S`. Продукт копируется целиком.
3. **Результаты подделываются.** `state` в `localStorage` и «код прогресса» — редактируются руками, отчёт формируется на клиенте. Учитель не может доверять отчёту.
4. **Отчёт через Formspree** — сторонний зарубежный сервис получает имя ученика (ПДн → 152-ФЗ, трансграничная передача). Убрать до любого масштабирования.
5. **Нет пользователей** → нет истории, статистики, групп. Данные живут в браузере одного устройства.
6. **1,5 МБ на страницу** из-за base64-шрифтов и стикеров. На мобильном интернете — 3–5 с загрузки. В продукте шрифты и картинки — отдельные кэшируемые файлы.
7. **Формулы — ручная HTML-вёрстка** (`.ms/.msb/.fd`). Работает, но не масштабируется на другие номера; KaTeX даст то же качество из `$\sqrt{a^2+b^2}$`.
8. **Дублирование чертежей:** у вариантов свои SVG (48 шт.), хотя фигура та же — меняются только числа. Именно это решает `figure_spec` + генерация подписей.

## 3. Что оставить / вынести / переписать

### Оставить (переносится почти без изменений)
- Классификация 8 разделов × 56 прототипов → `topics`/`prototypes` + теги (`parallelepiped`, `cube`, `prism`, `pyramid`, `cone`, `cylinder`, `sphere`, `inscribed`, `circumscribed`).
- Тексты 224 задач → `task_templates.statement_md` (после конвертации `<i class="m">…<sub>1</sub>` → `$ABCDA_1B_1C_1D_1$`).
- Все SVG → `content/figures/*.svg` + запись в `files`; для вариантов без своего SVG — ссылка на SVG прототипа.
- Теория → `topics.theory_md` (8 блоков) с 14 иллюстрациями.
- `parseNum` → `src/tasks/core/normalize-answer.ts` (с тестами: `"3,5"`, `"7/2"`, `"−3"`, `" 12 "`).
- CSS-переменные, типографика, состояния `ok/bad/seen`, адаптивные правила → `globals.css` и Tailwind-токены. Шрифты — файлы в `public/fonts` (Lora/Carlito/Pagella — лицензии OFL, ок).
- Микротексты: письмо учителя, фразы результата («Блестяще!», «Ошибки разберём вместе»), стикеры → `assignments.message`, `i18n/ru.json`.
- Логика «отработки» → алгоритм `practice`: слабые прототипы → следующий вариант/новый seed.

### Вынести на сервер
- `ANS`, `VAR[*].a` → таблица `answers` (недоступна клиенту).
- `check()` → Server Action `submitAnswer` (+ запись `attempts`).
- `reveal()` → `revealSolution` с фиксацией `solution_viewed`.
- `buildReport()` / `renderSummary()` → запросы к `attempts`/`statistics`; таблица результатов в кабинете учителя.
- Таймер → серверные метки `attempts.submitted_at` и `client time_spent_ms` c проверкой.

### Переписать
- `state`/`localStorage`/экспорт кода → аккаунт ученика; локально остаётся только черновик введённого ответа.
- Formspree-отправка → удалить.
- Рендер карточек строками HTML (`el.innerHTML = '<article…'`) → React-компоненты `TaskCard`, `AnswerInput`, `FigureSvg`, `TheoryBlock`, `SectionSummary`.
- HTML-формулы → KaTeX.

### Удалить
- Кнопка «Сбросить всё» в текущем виде (в продукте — только учитель может переназначить).
- Уведомление про «просмотрщик» — неактуально.

## 4. План извлечения контента (задача для Claude Code, 1 день)

Скрипт `scripts/import-legacy-dz3.ts`:
1. Прочитать `legacy/dz_stereometria_3.html`, вырезать `SECS`, `ANS`, `VAR`, карточки `#t1…#t56` (текст, SVG, `proto`), блоки `details.theory`.
2. Сформировать:
   ```
   content/topics/ege-math-03.json          — 8 разделов (theory_md, order)
   content/prototypes/03-stereometry/p01.json … p56.json
     { code, section, name, tags, statement_md, answer, figure: 'p01.svg', variants: [{statement_md, answer, figure?}] }
   content/figures/03/p01.svg … + v01_1.svg …
   ```
3. Конвертер HTML-математики → LaTeX (регэксп-таблица: `<i class="m">X<sub>1</sub></i>` → `$X_1$`, `.ms/.msb` → `\sqrt{…}`, `.fd` — display-формула). Проверить визуально на 10 случайных.
4. `pnpm content:import` → в БД: 56 `prototypes`, 224 `task_templates` со статическими параметрами, 224 `answers`.
5. Тест: для каждой импортированной задачи `checkAnswer(answer, String(answer).replace('.',','))` → true; число задач = 224; ни у одного шаблона нет пустого текста.

Что мне нужно от тебя: **есть ли скрипт, которым генерировались SVG** (Python/JS)? Если да — он ложится в основу `src/geometry` и экономит 2–3 недели.
