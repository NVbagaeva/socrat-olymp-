# Поиск: что настроить руками

Код сайта уже готов. Ниже — то, что делается в панелях сервисов и в
настройках репозитория. Порядок важен: сначала хостинг, потом
Вебмастер.

## 1. Timeweb: зеркало и SSL

Главное зеркало — `https://budetege.ru` без www. Редиректы прописаны в
`app/public/.htaccess`: с www, с `/index.html`, со старых адресов `/ege/`
и `/about.html`. Чтобы они заработали, на хостинге нужно проверить три
вещи.

1. **SSL-сертификат покрывает `www.budetege.ru`.**
   Панель Timeweb → «SSL-сертификаты» → сертификат домена `budetege.ru`.
   В списке доменов сертификата должны быть оба имени: `budetege.ru` и
   `www.budetege.ru`. Если www нет — перевыпустите бесплатный сертификат
   Let's Encrypt, отметив оба имени. Без этого браузер покажет
   предупреждение раньше, чем сработает редирект.
   Проверка из терминала:
   ```
   curl -sI https://www.budetege.ru/ | head -3
   ```
   После выкладки должно быть `HTTP/2 301` и `location: https://budetege.ru/`.

2. **www привязан к тому же сайту.**
   Панель → «Домены и поддомены» → `budetege.ru`. Поддомен `www` должен
   вести в ту же папку `public_html`, а не в отдельную. Сейчас так и есть
   (www отдаёт тот же сайт) — просто не меняйте.

3. **Редирект http → https включён.**
   Панель → «Сайты» → `budetege.ru` → «Перенаправлять на HTTPS» —
   включено. Сейчас работает: `http://budetege.ru/` отвечает 301 на
   https. Если в панели есть отдельная галочка «Перенаправлять с www» —
   её можно включить тоже, правило в `.htaccess` с ней не конфликтует.

Проверить всё одной командой после выкладки:
```
for u in http://budetege.ru/ http://www.budetege.ru/ https://www.budetege.ru/zadaniya/13/ https://budetege.ru/index.html https://budetege.ru/ege/ https://budetege.ru/net-takoy/; do
  printf "%-45s " "$u"; curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' "$u"
done
```
Ожидается: 301 на `https://budetege.ru/…` у первых пяти и 404 у последнего.

## 2. Переменные репозитория

GitHub → репозиторий → Settings → Secrets and variables → Actions →
вкладка **Variables** (не Secrets: значения публичные, они и так видны в
коде страниц) → New repository variable.

| Имя | Что вписать | Где взять |
|---|---|---|
| `NEXT_PUBLIC_YANDEX_VERIFICATION` | код из метатега Вебмастера, только значение `content` | Яндекс Вебмастер → Добавить сайт → способ «Мета-тег» |
| `NEXT_PUBLIC_GOOGLE_VERIFICATION` | код из метатега Search Console, только `content` | Search Console → Добавить ресурс «Префикс URL» → способ «Тег HTML» |
| `NEXT_PUBLIC_METRIKA_ID` | номер счётчика, только цифры | Метрика → Добавить счётчик |
| `INDEXNOW_KEY` | ключ IndexNow: 8–128 латинских букв, цифр и дефисов | придумать или сгенерировать, см. п. 5 |

После добавления переменных перезапустите выкладку: Actions → Deploy →
Run workflow. Пустая переменная — метатега, счётчика или файла ключа
просто нет, сайт собирается как раньше.

## 3. Яндекс Вебмастер

1. webmaster.yandex.ru → «Добавить сайт» → `https://budetege.ru`.
2. Способ подтверждения — «Мета-тег». Из строки
   `<meta name="yandex-verification" content="0123abcd…" />` скопируйте
   только `0123abcd…` в переменную `NEXT_PUBLIC_YANDEX_VERIFICATION`,
   перезапустите выкладку, нажмите «Проверить».
3. «Индексирование» → «Файлы Sitemap» → добавить
   `https://budetege.ru/sitemap.xml`.
4. «Индексирование» → «Переезд сайта»: проверьте, что главное зеркало —
   `https://budetege.ru` без www. Если Вебмастер видит www отдельным
   сайтом — добавьте его тоже и укажите переезд на без-www.
5. «Инструменты» → «Анализ robots.txt»: должен загрузиться без ошибок.
6. «Инструменты» → «Валидатор микроразметки»: вставьте адрес
   `https://budetege.ru/zadaniya/13/` — должны найтись BreadcrumbList,
   LearningResource, Organization, WebSite.

## 4. Google Search Console

1. search.google.com/search-console → «Добавить ресурс» → «Префикс URL»
   → `https://budetege.ru/`.
2. Способ — «Тег HTML»: значение `content` — в
   `NEXT_PUBLIC_GOOGLE_VERIFICATION`, перезапустить выкладку, «Подтвердить».
3. «Файлы Sitemap» → `sitemap.xml`.

## 5. IndexNow (Яндекс)

IndexNow сообщает Яндексу об изменённых страницах сразу после выкладки,
не дожидаясь обхода.

1. Придумайте ключ — например, 32 случайные латинские буквы и цифры.
   Можно так: `openssl rand -hex 16`.
2. Впишите его в переменную `INDEXNOW_KEY` (п. 2).
3. Перезапустите выкладку. Сборка положит файл ключа
   `https://budetege.ru/<ключ>.txt`, а последний шаг выкладки отправит
   Яндексу список изменённых страниц. Ответ Яндекса — в журнале шага
   «Сообщить Яндексу об изменённых страницах (IndexNow)».

Как сайт понимает, что страница изменилась: при сборке у каждой страницы
считается отпечаток текста (`app/out/seo-state.json`), а выкладка
скачивает прошлый отпечаток с сайта. Изменился текст — новая дата
`lastmod` в `sitemap.xml` и адрес в списке IndexNow. Первая выкладка
списка не шлёт: сравнивать не с чем, Яндекс возьмёт карту сайта.

## 6. Яндекс Метрика

1. metrika.yandex.ru → «Добавить счётчик» → адрес `budetege.ru`.
   Вебвизор можно не включать: код счётчика на сайте его не запускает.
2. Номер счётчика — в переменную `NEXT_PUBLIC_METRIKA_ID`.
3. Цели: «Настройка» → «Цели» → «Добавить цель» → тип
   «JavaScript-событие», идентификатор — ровно как в таблице:

| Цель | Идентификатор | Когда срабатывает |
|---|---|---|
| Начал тренировку | `trenirovka_start` | нажата «Начать тренировку» в любом тренажёре раздела (параметр `razdel` — номер раздела) |
| Сформировал вариант | `variant_sobran` | «Сформировать» на «Собрать вариант» или «Сгенерировать» в генераторе раздела (параметр `istochnik`) |
| Скачал бланк | `blank_skachan` | скачан бланк ЕГЭ из блока «Бланки» (параметр `blank`) |

Счётчик грузится после того, как страница загрузилась и браузер
освободился (`lazyOnload`), поэтому на скорость первой отрисовки и
оценку Lighthouse он не влияет.

## 7. Что проверить через неделю

- Вебмастер → «Страницы в поиске»: нет адресов с www, `/index.html`,
  `/styleguide/`, `/kabinet/`, `…/index.txt`, адресов с `?seed=`.
- Вебмастер → «Диагностика»: нет ошибок robots.txt и sitemap.
- Метрика → «Конверсии»: цели начали считаться.
