# Бакет для фото решений второй части (Yandex Object Storage)

Инструкция владельца. Фото решений второй части будут лежать в
отдельном бакете Yandex Object Storage (решение В-4 плана
[plans/cabinet-v2.md](plans/cabinet-v2.md)). Код загрузки придёт в
PR 1в; бакет можно создать заранее. Сайт и сервер к нему пока не
обращаются.

Бакет — отдельный от бакета копий базы (`docs/SERVER.md`, шаг 3), и ключ
к нему — свой: если утечёт ключ фото, копии базы останутся закрыты, и
наоборот.

Названия кнопок в консоли Yandex Cloud время от времени меняются. Если
какой-то кнопки нет на месте — ищите по смыслу шага.

## 1. Каталог

Платёжный аккаунт и каталог уже есть, если создан бакет копий. Тогда
переходите к шагу 2.

Если нет:

1. Откройте [консоль Yandex Cloud](https://console.yandex.cloud) и войдите
   своим Яндекс ID.
2. Создайте платёжный аккаунт (нужна карта; в начале обычно дают
   стартовый грант).
3. В облаке создайте каталог (folder), например `budetege`.

## 2. Бакет

1. В каталоге откройте **Object Storage → Создать бакет**.
2. Заполните:
   - **Имя** — например, `budetege-chast2-foto`. Имя видно в адресах
     файлов, поэтому без имён и фамилий.
   - **Доступ на чтение объектов, к списку объектов и к настройкам** —
     **ограниченный** для всех трёх. Публичного доступа у фото учеников
     быть не должно.
   - **Класс хранилища** — стандартное.
   - **Максимальный размер** — 10 ГБ. Этого хватит надолго: одно фото
     после сжатия в браузере до 1,5 МБ, к задаче до 6 фото. Предел
     защищает от неожиданного счёта.
3. Нажмите **Создать бакет**.

## 3. Правило очистки (страховка)

Сайт сам удалит фото после конца учебного года, в котором выдано ДЗ.
Правило ниже — страховка на случай сбоя: бакет удалит всё, что старше
двух лет.

1. Откройте бакет → **Жизненный цикл** → **Настроить**.
2. Добавьте правило:
   - **Описание** — `strakhovka-2-goda`;
   - **Префикс** — пусто (весь бакет);
   - **Удаление объектов** — через **730** дней.
3. Сохраните.

## 4. Сервисный аккаунт и ключ

1. В каталоге откройте **Identity and Access Management → Сервисные
   аккаунты → Создать сервисный аккаунт**.
2. **Имя** — `budetege-chast2-foto`. Роль на каталог не назначайте.
3. Вернитесь в бакет → **Права доступа (ACL бакета)** → добавьте этот
   сервисный аккаунт с правами **READ и WRITE**. Так ключ работает только
   с этим бакетом, а не со всеми бакетами каталога.
   - Если в вашей консоли ACL бакета нет, назначьте сервисному аккаунту
     роль `storage.editor` на каталог. Это шире: ключ увидит и бакет
     копий. Тогда лучше вынести бакет фото в отдельный каталог.
4. Откройте сервисный аккаунт → **Создать новый ключ → Создать
   статический ключ доступа**. Описание — `server`.
5. Консоль покажет **идентификатор ключа** и **секретный ключ**. Секрет
   показывается один раз: сразу перенесите оба значения в GitHub
   (шаг 5). Никуда больше их не копируйте и не присылайте в чат.

## 5. GitHub

Репозиторий → **Settings → Secrets and variables → Actions**.

**Secrets** (вкладка Secrets → New repository secret):

| Имя | Значение |
|---|---|
| `S3_FOTO_ACCESS_KEY_ID` | идентификатор ключа из шага 4 |
| `S3_FOTO_SECRET_ACCESS_KEY` | секретный ключ из шага 4 |

**Variables** (вкладка Variables → New repository variable):

| Имя | Значение |
|---|---|
| `S3_FOTO_BUCKET` | имя бакета из шага 2, например `budetege-chast2-foto` |

Адрес хранилища (`https://storage.yandexcloud.net`) и регион
(`ru-central1`) вписывать не нужно: они одинаковы для всех бакетов, и
сервер возьмёт их сам.

## 6. Что дальше

Напишите «бакет для фото готов». В PR 1в:

- на сервер добавится контейнер Storage (служба файлов Supabase), он
  будет класть фото в этот бакет; браузер к бакету напрямую не ходит,
  поэтому настраивать CORS у бакета не нужно;
- кнопка «Сервер: развернуть» передаст ключ на сервер;
- перед включением будет замер памяти сервера (`docs/hosting-lite.md`,
  раздел 4).

## Сколько стоит

Хранение стандартного класса — порядка рублей за гигабайт в месяц, плюс
операции записи и чтения — копейки за тысячи запросов. Актуальные цены —
на странице тарифов Object Storage в Yandex Cloud. Счёт растёт только с
числом фото: 1000 фото по 1,5 МБ — около 1,5 ГБ.

## Для политики конфиденциальности

Фото решений — персональные данные ученика (почерк, возможно, имя на
листе). Хранятся в России (Yandex Object Storage, регион
`ru-central1`), видят их только ученик и учитель этого ДЗ, срок — до
конца учебного года, в котором выдано ДЗ.
