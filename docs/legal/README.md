# Правовые документы и согласия

Политика, согласие на обработку персональных данных и пользовательское
соглашение на сайте, галочки при регистрации, таблица согласий, баннер
cookie. Исходник текстов — `ishodnik-dokumenty-pd.md` (файл Натальи,
как он пришёл).

## Что заполнить один раз

Файл **`app/src/content/legal/operator.json`**:

```json
{
  "fio": "Фамилия Имя Отчество",
  "pochta": "privacy@budetege.ru",
  "data": "15.10.2026"
}
```

| Поле | Куда подставляется | Формат |
|---|---|---|
| `fio` | вместо [ФИО]: три документа, подвал «Оператор персональных данных: …», письмо родителю | полностью, минимум два слова |
| `pochta` | вместо [ПОЧТА]: три документа, письмо родителю | адрес почты |
| `data` | вместо [ДАТА]: «Редакция от …» на трёх страницах; она же — версия документов в таблице согласий | ДД.ММ.ГГГГ |

Пока хоть одно поле не заполнено, `pnpm build` останавливается и пишет,
какое поле не так. Деплой из main при этом тоже не пройдёт. Превью, проверки
и сборки PDF в CI собирают черновик (`LEGAL_DRAFT=1` в workflow), и на
страницах документов сверху видна жёлтая плашка «Черновик».

## Новая редакция документов

1. Поправить текст в `app/src/content/legal/<документ>.md` и тот же текст —
   в `ishodnik-dokumenty-pd.md`: проверка `pnpm test:legal` сверяет их
   построчно и упадёт, если тексты разойдутся.
2. Сменить `data` в `operator.json`.
3. В базе: `insert into public.legal_editions (version) values ('ГГГГ-ММ-ДД');`
   с той же датой. После этого при входе каждый пользователь увидит окно
   «Документы обновлены» с галочками заново (`documents_to_accept()`).

## Что пока не подключено

Сервера с аккаунтами в проекте ещё нет (сессии С-1 «Сервер» и С-3
«Аккаунты» в `docs/CABINET_UX_SPEC.md`). Поэтому:

- форма регистрации, окно «Документы обновлены», плашка родителя и блок
  «Документы и данные» готовы как компоненты, но на сайте их нет — они
  работают только на витрине `/styleguide/soglasiya/` в `pnpm dev`;
- миграция проверена на PostgreSQL (`pnpm test:soglasiya-sql`), но
  применится, когда появится Supabase;
- письма родителю нужен почтовый сервис: сервер вызывает
  `issue_parent_token`, собирает письмо `buildParentLetter` и отправляет;
- страница подтверждения по ссылке из письма (`/soglasie-roditelya/?t=…`)
  вызывает `confirm_parent_consent` — её делает С-3;
- «Удалить аккаунт» и «Выгрузить мои данные» — функции
  `delete_my_account()` и `export_my_data()` в базе и кнопки в компоненте.
  Кнопки «Удалить аккаунт» на сайте раньше не было.

Что сервер С-3 должен соблюсти, записано в начале миграции: регистрация
только через сервер (открытая регистрация в GoTrue выключена), IP запроса
кладётся в `raw_user_meta_data.signup_ip`, у новых таблиц с данными
пользователя — `references auth.users on delete cascade` (иначе проверка
№14 упадёт), таблицы прогресса в политике RLS вызывают
`can_save_progress(user_id)`, `purge_old_consents()` запускается раз в сутки.

## Проверки

| Команда | Что проверяет |
|---|---|
| `pnpm test:legal` | тексты совпадают с исходником; оглавления; operator.json; правила регистрации; письмо родителю |
| `pnpm test:soglasiya-sql` | на временном PostgreSQL: без галочек пользователь не создаётся, запись согласия с типом, версией, временем и IP, родитель, повтор письма, новая редакция, выгрузка, удаление без журнала согласий, очистка через 3 года |
| `pnpm test:soglasiya-site` | после сборки: страницы открываются без входа, `index, follow`, оглавление, якоря, подвал, баннер один раз |
| `pnpm test:soglasiya-site --demo http://127.0.0.1:3000` | на витрине в `pnpm dev`: регистрация без галочек невозможна, запись согласия, письмо и подтверждение, окно новой редакции, удаление |
