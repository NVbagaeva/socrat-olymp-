# План своей онлайн-доски «Будет ЕГЭ»

Статус: **проект, ждёт «утверждаю»**. Кода нет.

## 0. Решения и рамки

- **Движок свой.** Холст, модель сцены, инструменты, фигуры, ввод с
  пера и пальцев, карточки задач, шаблоны пишем сами. Excalidraw,
  tldraw, Fabric.js, Konva и другие готовые доски и движки холста **не
  используем**.
- Сторонние библиотеки — только узкие, небольшие, с лицензией MIT,
  Apache-2.0 и подобными, которые разрешают коммерческое использование
  (раздел 3).
- **iPad со стилусом и телефон — с первого этапа.** Это входит в
  приёмку каждого этапа, а не отдельная задача «на потом».
- Доска — **продолжение банка задач**, а не копия МатДоски. Отличие
  этапа 2 (подсказки по шагам и «другой сюжет») держится на данных,
  которые у нас уже есть.
- До выхода доски на сайте только: «Своя доска с банком задач — в
  разработке, подписчики получат её первыми» (`positioning.md`).

## 2. Архитектура

### 2.1. Где живёт

- **Клиент:** страница `/doska/` в том же Next.js (статический экспорт,
  только клиент). Адрес доски — `/doska/?b=<id>#k=<ключ>`: ключ стоит
  после `#`, поэтому не попадает в логи сервера и в статистику.
- **Сервер доски:** контейнер `board` (Node.js) в `infra/lite/compose.yml`.
  Caddy проксирует `wss://api.budetege.ru/board`. Наружу новых портов
  не открываем.
- **Хранение:** PostgreSQL, тот же экземпляр. Новые таблицы через
  миграции в `supabase/migrations`.

### 2.2. Модель доски (своя)

```
Доска
 ├─ meta: название, владелец (репетитор), режим «листы», создана, ученики
 ├─ листы: упорядоченный список страниц (размер A4-альбом, фон: клетка/линия/чисто)
 └─ элементы (на листе):
     stroke   — штрих пера/маркера: точки [x, y, нажим], цвет, толщина, инструмент
     shape    — отрезок, стрелка, прямоугольник, окружность, треугольник,
                многоугольник; сплошная/пунктир
     text     — текст
     formula  — TeX-строка (рисуется KaTeX)
     task     — ссылка на задачу банка (раздел 2.5) + состояние: открытые
                подсказки, ответ показан, отмечено «сложно»
     template — шаблон: коорд. плоскость, тригокруг, схема №18… (этап 3)
     image    — картинка (этап 3)
```

Элементы хранятся в общем документе синхронизации (2.4), у каждого
элемента свой id. Порядок отрисовки — отдельный список. Отмена и повтор
действий — свои у каждого участника (репетитор не отменяет штрих
ученика).

### 2.3. Отрисовка и ввод (своё)

- **Canvas 2D**, два слоя:
  - нижний — готовые элементы; кэшируется по листам и перерисовывается
    только при изменениях;
  - верхний — то, что рисуется прямо сейчас (свой и чужие живые штрихи)
    и курсоры.
  Учитываем `devicePixelRatio`, рисуем только видимое.
- **Карточки задач и формулы — HTML-слой поверх холста.** Слой двигается
  вместе с холстом, а KaTeX и вёрстка карточек остаются те же, что на
  сайте: формулы чёткие при любом масштабе, верстать заново не нужно.
- **Ввод — Pointer Events:**
  - `pointerType` различает перо, палец и мышь; учитываем `pressure` и
    `getCoalescedEvents()`, чтобы линия пера была плавной;
  - **режим «пишу пером»:** когда пришло событие пера, касания пальцем не
    рисуют, а двигают и масштабируют холст (защита от ладони на iPad);
  - **два пальца** — сдвиг и масштаб; на компьютере — пробел + мышь,
    Ctrl + колесо;
  - `touch-action: none` на холсте; отключаем масштаб двойным тапом и
    «резинку» в iOS Safari.
- **Сглаживание штриха** — своё: упрощение точек + сплайн. Ширина
  меняется по нажиму.
- **Телефон:** та же доска, панель инструментов внизу и сворачивается.
  Полноценные режимы — «смотрю и пишу ответ» (пишет пальцем) и
  «смотрю». Карточка задачи на узком экране переносит текст.

### 2.4. Синхронизация в реальном времени

Сравнение вариантов:

| | Свой протокол на WebSocket | **Yjs + Hocuspocus** | Automerge |
|---|---|---|---|
| Что это | своё всё: операции, порядок, переподключение | CRDT-документ (Yjs, MIT) + сервер к нему (Hocuspocus, MIT) | CRDT на Rust/wasm (MIT) |
| Конфликты одновременных правок | пишем сами | решены библиотекой | решены библиотекой |
| Обрыв связи на телефоне, догон после | пишем сами (недели) | есть | есть |
| Размер в браузере | минимальный | ~30–40 КБ gzip (оценка, проверить сборкой) | больше, wasm |
| Сервер | свой | Hocuspocus: проверка доступа и сохранение в базу — точками расширения | свой |
| Сложность | высокая | низкая | средняя |

**Рекомендация: Yjs + Hocuspocus.** Это не доска, а слой
синхронизации данных: что лежит в документе, как рисуется и как
работает, — по-прежнему наше.
- **Живой штрих** уходит по «awareness» (временное состояние участника,
  в документ не пишется) порциями раз в ~30 мс. В документ штрих
  попадает целиком, когда перо поднято. Так ученик видит линию почти
  сразу, а история документа не раздувается.
- **Сохранение:** Hocuspocus складывает состояние документа (бинарный
  Yjs) в таблицу `board_docs` с задержкой в несколько секунд после
  правки. Отдельной кнопки «Сохранить» нет.
- **Задержка:** сервер в РФ, для учеников в РФ ожидаем десятки мс
  (оценка). Проверяем на этапе 1 замером: штрих на iPad → телефон
  через мобильный интернет.

⚠ Перед стартом этапа 1 проверить актуальные версии и лицензии Yjs и
Hocuspocus в их репозиториях (на момент проекта обе — MIT, по памяти).

### 2.5. Банк → доска

Сейчас у каждого номера свой формат. Вводим **один формат «задача для
доски»**: при сборке сайта каждый номер отдаёт его в
`/data/doska/<номер>/<прототип>.json`.

```ts
interface ZadachaDoski {
  id: string;              // «10:F001»
  nomer: number;           // 10
  prototype: string;       // «P01», на сайте «П-01»
  prototypeTitle: string;  // «Мост: длина ванты»
  istochnik: 'fipi' | 'syuzhet';   // бейдж — только по таблице positioning.md
  uslovieHtml: string;     // уже набрано KaTeX при сборке
  risunok?: string;        // SVG или адрес картинки
  otvetSeal: string;       // отпечаток ответа, как на сайте сейчас
  podskazki?: { vopros: string; varianty: string[]; vernyj: number }[];
  razborHtml?: string;     // этап 2+
}
```

- В документе доски хранится **только ссылка** (`id`) и состояние
  (сколько подсказок открыто, показан ли ответ). Текст подтягивается из
  статики сайта: доска лёгкая, а исправление задачи в банке сразу видно
  на всех досках.
- **«Другой сюжет»** — следующий `id` того же прототипа, которого ещё не
  было на этой доске.
- **Ответ видит только репетитор.** Ученику ответ не уходит открытым
  текстом. Сейчас на сайте так же: в браузер уходит отпечаток.
- **Порядок номеров:**
  - этап 1 — №6, 7, 10, 11: банк уже в JSON, есть подсказки и ФИПИ;
  - этап 2 — №1, 3, 4, 5, 13;
  - дальше — остальные по одному.
  На каждый номер нужен свой адаптер — это главный «невидимый» объём.

### 2.6. Доступ и данные

- **Репетитор** входит существующим аккаунтом (GoTrue) и создаёт доску
  ученику или группе.
- **Ученик** заходит по ссылке без регистрации и вводит имя. Сервер
  проверяет пару «id доски + ключ» в `onAuthenticate` Hocuspocus. Ключ
  можно перевыпустить — старая ссылка перестанет работать.
- **Таблицы (миграции):**
  - `boards`: id, owner, title, created_at, key_hash, archived;
  - `board_docs`: board_id, state bytea, updated_at;
  - позже `board_tasks` — журнал задач на доске для повторения ошибок.
- **Персональные данные:** имя ученика — только то, что он ввёл; храним
  в РФ, как остальной кабинет. Фото и картинки — этап 3: в Yandex Object
  Storage (уже используется для копий базы) или на диске VDS. Решаем на
  этапе 3.
- **Лимиты:** до 100 досок на репетитора (как у МатДоски — разумный
  потолок, можно менять), размер документа, частота сообщений.

### 2.7. Хостинг и стоимость

- **Этапы 1–2:** тот же VDS, ещё один контейнер. Дополнительных платежей
  не ожидаю.
- **Нагрузка:** урок — 2–5 участников, трафик — штрихи. Сколько
  одновременных досок выдержит текущий VDS, **не знаю — измерим
  нагрузочным тестом** в конце этапа 1, до раздачи репетиторам.
- Если не хватит, вынесем `board` на отдельный VDS в том же ДЦ. Цену
  назову по прайсу провайдера на тот момент, не по памяти.

своё будет заметно хуже на iPad.

## 4. Этапы

Оценки — в рабочих днях разработки при вашей проверке после каждого
шага. Это оценка, не обещание: точнее станет после первой недели
этапа 1, тогда пересчитаю. Каждый этап заканчивается **рабочей
доской**, которую можно дать репетиторам.

### Этап 1. «Рисуем вдвоём по ссылке + задача из банка на доске»

**Объём: ~25–35 рабочих дней.**

Что входит:
1. **Сервер:**
   - контейнер `board` (Hocuspocus) в `infra/lite`, путь в Caddy;
   - миграции `boards`, `board_docs`;
   - проверка в CI, как у остального сервера (`lite-server.yml`).
2. **Холст:**
   - листы (добавить, листать, удалить), фон «клетка»;
   - масштаб и сдвиг: два пальца, пробел + мышь, Ctrl + колесо.
3. **Инструменты:**
   - перо с нажимом, маркер, ластик (стирает штрих целиком);
   - отрезок, стрелка, прямоугольник, окружность, треугольник;
     сплошная и пунктирная линия;
   - текст; 3 цвета + выбор, 3 толщины;
   - выделение, перемещение, удаление;
   - отмена и повтор (свои у каждого участника).
4. **Вдвоём:**
   - ссылка для ученика без регистрации, ученик вводит имя;
   - живой штрих видно во время рисования, курсоры с именами;
   - значок «ученик на доске»;
   - после обрыва связи доска догоняет сама.
5. **Сохранение:** автоматическое. Доска живёт между уроками, в кабинете
   репетитора — список досок.
6. **Банк:**
   - шторка «Банк задач» → номер → прототип → задача → «На доску»;
   - номера 6, 7, 10, 11; бейдж «ФИПИ» / «Сюжет к П-…» по таблице;
   - ответ видит только репетитор.
7. **iPad и телефон:**
   - перо рисует, пальцы двигают; ладонь не рисует;
   - на телефоне — нижняя панель и карточка в одну колонку.
8. **Замеры:**
   - задержка штриха через мобильный интернет;
   - нагрузочный тест: N одновременных досок на текущем VDS.

**Что вы проверите руками:**
- [ ] Создать доску в кабинете → скопировать ссылку → открыть на телефоне
      без входа → ввести имя → вы на одной доске.
- [ ] iPad + Apple Pencil: линия тоньше и толще от нажима; ладонь на
      экране не оставляет следов; двумя пальцами — сдвиг и масштаб.
- [ ] Рисуете на iPad — на телефоне линия появляется во время
      рисования, а не после.
- [ ] Телефон пишет пальцем — вы видите на компьютере.
- [ ] Выключить Wi-Fi на телефоне на 30 секунд, порисовать на iPad,
      включить — телефон догнал всё.
- [ ] Отмена на iPad не стирает то, что нарисовал ученик.
- [ ] Банк → №10 → П-01 → «На доску»: условие и рисунок на доске,
      бейдж «ФИПИ»; у ученика нет ответа (проверить и в коде страницы).
- [ ] Закрыть всё, открыть доску завтра — всё на месте.
- [ ] Окружность, треугольник, пунктир, текст — двигаются и удаляются.

**Что можно дать репетиторам после этапа:** урок на доске по ссылке с
задачами №6, 7, 10, 11.

### Этап 2. «Подсказки по шагам + другой сюжет»

**Объём: ~15–20 рабочих дней.**

Что входит:
1. **Подсказки на карточке:**
   - репетитор нажимает «Следующая подсказка» — у ученика появляется
     вопрос с вариантами;
   - ученик выбирает вариант, верно или нет видят оба;
   - следующий вопрос открывается после верного ответа, как на сайте.
2. **«Другой сюжет этого прототипа»** — одна кнопка на карточке: новая
   задача того же прототипа, без повторов на этой доске. Счётчик
   «4 ФИПИ · 24 сюжета · было на доске 3».
3. **Ответ ученика в карточке** — проверка по отпечатку, как в тренажёре.
4. **Формулы:** инструмент «Формула» — MathLive (клавиатура на iPad и
   телефоне) → KaTeX на доске.
5. **Новые номера в банке доски:** №1, 3, 4, 5, 13 (адаптеры в формат
   «задача для доски»).
6. **Отметка «Сложно»** на карточке — пишется в `board_tasks`, пригодится
   на этапе 3.

**Что вы проверите руками:**
- [ ] №10, задача ФИПИ → «Подсказка»: ученик на телефоне видит вопрос с
      тремя вариантами; неверный — отмечен, следующий не открылся;
      верный — открылся следующий.
- [ ] «Другой сюжет» 5 раз подряд → 5 разных задач того же прототипа,
      ни одна не повторилась; счётчик растёт.
- [ ] Ученик вводит ответ в карточке — «верно/неверно», правильного
      ответа он не видит.
- [ ] Формула с дробью и корнем на iPad через экранную клавиатуру —
      видна у ученика, не расплывается при масштабе.
- [ ] Задачи №1, 3, 4, 5, 13 встают на доску; у №4–5 бейджа «ФИПИ» нет.

**Что можно дать репетиторам:** урок, где ученик проходит задачу по
подсказкам, и бесконечный запас сюжетов к прототипу.

### Этап 3. «Шаблоны, ДЗ и PDF»

**Объём: ~25–35 рабочих дней.**

Что входит:
1. **Шаблоны:**
   - координатная плоскость (сетка, оси, подписи);
   - тригонометрический круг (отметить угол, проекции);
   - **график с ползунком параметра** — на основе нашей `lib/graph`;
   - схемы №18 из «Ключевых схем»;
   - опорные задачи метода №19 («Метод 3 — на доску»).
2. **ДЗ из доски:**
   - «+ ДЗ» на карточке → домашка в кабинете (те же таблицы
     `kabinet`);
   - репетитор выбирает режим: без подсказок / по шагам / с разбором;
   - ученик решает в кабинете, результат — у репетитора.
3. **Повторение по прототипу:**
   - задачи с отметкой «Сложно» и ошибки из ДЗ → в начале следующего
