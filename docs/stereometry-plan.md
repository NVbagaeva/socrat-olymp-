## 1. Аудит эталона: как устроен №12 и соседние разделы

### 1.1. Главная находка

**№12 — эталон по виду, но не по устройству.** Страница подтемы №12
(`components/tasks/FunctionTopicPage.tsx` + `TopicTabs.tsx`) — один
клиентский компонент, который переключает вкладки состоянием (`?vkladka=`).
Новые разделы (№1, №10, №11, №16) собраны иначе и лучше: группа маршрутов
`app/zadaniya/N/(razdel)/` с `layout.tsx` → `ShellN` → `RazdelTabs`, у
каждой вкладки свой адрес. Шапка и лента живут в layout и не
перерисовываются при смене вкладки.

Решение: **устройство берём у №1/№11 (маршруты + `RazdelTabs`), вид и
поведение — у №12** (пилюля раздела, bottom-sheet, «Содержание»,
подсказки-вопросы, генератор, сессия тренажёра). Всё, чего не хватает
`RazdelTabs` по сравнению с `TopicTabs`, доносим в общий компонент, а не
копируем.

### 2.3. Два движка

| | `lib/solid` | `lib/zadanie15` + `dvizhok` |
|---|---|---|
| Арифметика | float | точная (дроби, k√m) |

### 4.2. Данные

```
content/stereo/
  zadanie3.ts, zadanie15.ts      — шапка, вкладки, тексты интерфейса
  teoriya3/glava-00 … glava-10.ts — главы теории №3 (карточки, примеры, сцены)
  teoriya15/glava-1 … glava-6.ts
  o-zadanii3.ts, o-zadanii15.ts  — типы задач, «Что нужно уметь», критерии
  repetitory3.ts                 — уроки
lib/stereo/                      — общее ядро (п. 4.3)
lib/zadanie3/                    — банк №3 (остаётся), + razbor/ развёрнутые решения,

lib/zadanie15/                   — ядро сечений (остаётся), + bank/ прототипы №15
```

Глава теории — данные, а не JSX: массив блоков (`opredelenie`,
`svoystva`, `priznaki`, `teorema`, `formula`, `primer`, `vazhno`,
`vyvod`, `chertezh`, `podrazdel`). Правило «Важно/Вывод не стоят сами по
себе» проверяется автотестом: у блоков `vazhno` и `vyvod` обязательное
поле `zadacha` (условие + разбор) — без него сборка падает.

### 4.3. Один чертёжный движок `lib/stereo`

Цель — одно ядро для теории, «О задании», опорных, тренажёра, генератора
и №15.

1. **Модель.** Тело описывается гранями (многогранники) или параметрами
   (цилиндр, конус, усечённый конус, шар). Берём модели и построители
   `lib/solid/figures.ts`, добавляем в `lib/zadanie15/core/polyhedron.ts`
   призму (n-угольную, прямую и наклонную), пирамиду (в т. ч. правильную)
   и тетраэдр — для точных сечений №15.
2. **Лёгкий интерактивный просмотр без three.js.** Школьный режим
   `dvizhok` и так рисует всё в SVG, WebGL-холст в нём пуст. Выносим
   проекцию, видимость, подписи и обработку жестов в `lib/stereo/view`
   (≈15–20 КБ без three.js): вращение пальцем и мышью, кнопки «Сбросить
   вид», «Вид спереди/сверху». Тела вращения в SVG: эллипсы оснований,
   образующие-касательные, пунктир задних дуг. three.js остаётся только
   для режима «3D» в №15 и грузится по кнопке.
3. **Пошаговая подсветка.** Сцена получает слои `shagi: [{ ids, podpis }]`:
   на шаге N элементы шага жирные и цветные, прошлые шаги — обычные,
   будущие скрыты. Этот же API у решений тренажёра, примеров теории,
   разборов «О задании» и листа учителя.
4. **Подписи** не налезают друг на друга и на линии: раскладка `metki.ts`
   №15 + препятствия-линии из `lib/planimetriya/kollizii.ts`; зазор от
   линии ≥ 4 px; ключевые элементы — `stroke-width` ×1,6 и полужирная
   подпись. Проверка — автотест на пересечения прямоугольников подписей и
   отрезков для каждого чертежа сборки.
5. **SSR-постер.** На сборке `lib/solid` рисует исходный вид тем же стилем;
   интерактив подключается, только когда чертёж попал в экран
   (IntersectionObserver), и только по первому касанию — на слабых
   телефонах страница теории не грузит ни одного лишнего мегабайта.
6. **Производительность.** Перерисовка только при движении; видимость —
   по рёбрам на кадр, а не по всем отрезкам × 48 проб (кэш порядка граней
   на угол поворота, шаг 1°); подписи раскладываются после остановки
   вращения, во время вращения — без раскладки. Бюджет: ≤ 8 мс на кадр
   на эмуляции 4× CPU slowdown, проверка в Playwright.

### Этап 1в (движок)

Решение по п. 4.3 уточнено: интерактивный чертёж построен на `lib/solid`
без three.js. Школьный режим `dvizhok` и так рисовал всё в SVG, а у
`lib/solid` уже есть все тела №3. Вращение — тот же ортогональный вид
под другим ракурсом.

Сделано:
- **Ракурс.** `lib/solid/project.ts`: `orthoAt(азимут, подъём)`, вид
  по умолчанию — он же под углами 28° и 25°.
- **Опции рендера.** `renderSolid(model, { view, shag, ustoychivo })`.
  Шаги решения задаются полем `shag` у линий, сечений, углов, точек,
  чисел и подписей. На своём шаге элемент выделен (толще, акцентным
  цветом, подпись полужирная), до своего шага не рисуется. `ustoychivo`
  держит масштаб и рамку по описанной сфере, чтобы чертёж не прыгал при
  вращении.
- **Скорость подписей.** Расстановка отсекает далёкие линии по рамкам и
  стала в 10 раз быстрее. Средний кадр на всех чертежах банка — 0,7 мс.
- **Статичные чертежи не изменились:** 1088 рисунков совпадают с `main`
  байт в байт.
- **Компонент `components/stereo/Chertezh3d`.**

    касанию: +2 КБ к загрузке страницы.
  - Поворот мышью; пальцем — вбок, вертикальный жест остаётся прокрутке.
    Ещё есть стрелки и кнопки «Сбросить вид», «Сверху».
  - Шаги «Назад / Далее» с подписью в KaTeX.
  - На слабом телефоне долгий кадр пропускает следующий.
- **Примеры в теории.** Диагональ куба (глава 0 №3) и сечение куба

Ограничения и что дальше:
- **Правильные основания в точном ядре.** Треугольник и шестиугольник
  требуют $\sqrt3$ в координатах, а ядро считает в дробях. Сечения

  углы) для правильных оснований — этап 5б: ортонормированная запись
  через `surd` или аффинная система с метрикой.
- **Витрина `/zadaniya/15/vitrina/` и режим «3D»** (three.js) остаются
