# Вход и личный кабинет: пробный режим

Документ для владельца проекта. Что такое пробный режим, как он
включается, что хранится в базе и что отложено до регистрации
настоящих учеников.

Коротко: сайт остаётся статическим на Timeweb. Вход и база живут на
своём сервере в Москве — `api.budetege.ru` (как его запустить —
[SERVER.md](SERVER.md)). Сайт обращается к нему прямо из браузера.
Зарегистрироваться могут только адреса из списка `ALLOWED_EMAILS`:
это секрет GitHub, в репозитории и в коде сайта адресов нет.

Пока флаг входа не включён в настройках GitHub, на сайте ничего не
меняется: ни кнопки «Войти», ни лишнего кода — сайт собирается и
работает ровно как раньше.

## Флаги

Все — Variables репозитория (**Settings → Secrets and variables →
Actions → вкладка Variables**). Значения публичные, поэтому именно
Variables, а не Secrets.

| Variable | Что делает | По умолчанию |
|---|---|---|
| `NEXT_PUBLIC_AUTH_ENABLED` | `1` — вход на сайте включён: работают `/voyti/` и `/kabinet/`. Нет или `0` — сайт как раньше, страницы входа отвечают «Вход пока недоступен», кода входа в сборке нет | выключен |
| `NEXT_PUBLIC_AUTH_IN_HEADER` | `1` — кнопка «Войти» видна в шапке и в меню телефона: на компьютере таблетка со значком и словом, на телефоне кружок со значком (название рядом со знаком сайта тогда прячется — иначе не помещается). «Начать бесплатно» и с кнопкой ведёт в банк заданий: регистрация пока по приглашению. Нет или `0` — кнопки нет, страница `/voyti/` открывается только по прямой ссылке. Кружок с инициалами после входа показывается в любом случае | выключен |
| `NEXT_PUBLIC_SUPABASE_URL` | адрес сервера входа, `https://api.budetege.ru` | записывает кнопка «Сервер: ключ для сайта» |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | публичный ключ сервера | записывает та же кнопка |

Пробный режим — это `NEXT_PUBLIC_AUTH_ENABLED=1` без
`NEXT_PUBLIC_AUTH_IN_HEADER`: вы входите по прямой ссылке
`https://budetege.ru/voyti/`, остальные посетители входа не видят.

После смены любой переменной — **Actions → Deploy → Run workflow**:
значения подставляются при сборке сайта.

## Что получилось

| Где | Что |
|---|---|
| `/voyti/` | Вкладки «Войти» и «Зарегистрироваться». Вход: почта, пароль, «Запомнить меня», «Забыли пароль?». Регистрация: имя, почта, пароль от 8 знаков, две карточки «Я ученик» и «Я репетитор»; ученику — год рождения, младше 18 — почта родителя; две галочки согласий со ссылками на соглашение и согласие, ссылка на политику |
| `/voyti/podtverzhdenie/` | Куда ведёт ссылка из письма подтверждения |
| `/voyti/novyy-parol/` | Куда ведёт ссылка из письма сброса пароля |
| `/kabinet/` | Один адрес на все роли. Вкладка «Кабинет»: ученику — «Прогресс», «Мои ошибки», «Отложенные», «Домашние задания», «Мой класс»; репетитору — «Мои классы», «Домашние задания», коды комплектов. Разделы пока с пустыми состояниями: наполняются по этапам, первым — №8. Вкладка «Профиль»: имя (меняется), почта, роль (не меняется), что сохранено, документы и выгрузка данных, «Выйти», «Удалить аккаунт» |
| Первый вход | «Перенести ваш прогресс с этого устройства в кабинет?» Да / Нет — если в браузере есть прогресс №8. Спрашивается один раз |
| Шапка после входа | Кружок с инициалами, в меню «Мой кабинет» и «Выйти» |
| Чужая почта | «Регистрация пока по приглашению.» Список адресов браузер не видит |
| Флаг выключен | Кнопок нет, страницы входа говорят «Вход пока недоступен», SDK в сборку не попадает |

Одно честное отступление, следствие статического хостинга: **cookie
сессии httpOnly нет.** Статический сайт не может поставить такую
cookie. Сессия хранится в хранилище браузера (localStorage при
«Запомнить меня», иначе sessionStorage), с ротацией refresh-токена.
Выход отзывает сессию на сервере. Сторонних скриптов на сайте нет,
поэтому украсть сессию скриптом неоткуда.

## Как устроена регистрация

Путь один, обходов нет:

1. Форма отправляет имя, роль, отметки двух галочек и дату редакции
   документов, которую человек видел (ученик — ещё год рождения и, если
   ему меньше 18, почту родителя).
2. Служба входа спрашивает базу (хук «перед созданием пользователя»):
   адрес есть в списке `ALLOWED_EMAILS`? Нет — отказ, сайт пишет
   «Регистрация пока по приглашению». Заодно хук запоминает IP запроса.
3. База создаёт пользователя, и два триггера проверяют всё ещё раз,
   уже не доверяя форме:
   - согласия: обе галочки стоят, редакция документов — текущая; в
     журнал согласий пишутся вид документа, редакция, время и IP,
     который сообщила служба входа (не форма);
   - роль: адрес в списке, роль — «ученик» или «репетитор». Стать
     администратором через форму нельзя.
4. На почту уходит письмо «Подтвердите почту». До перехода по ссылке
   войти нельзя.

**Роль после регистрации не меняется** — ни в кабинете, ни запросом из
браузера: от роли зависит, чьи данные человек видит. Ошиблись ролью —
удалите аккаунт в кабинете и зарегистрируйтесь заново.

**Администратор** — один на всю базу, назначается только на сервере:
секрет `ADMIN_EMAIL` и кнопка «Сервер: миграции». Аккаунт должен быть
уже зарегистрирован. Администратор перестаёт быть учеником или
репетитором, поэтому для него нужен отдельный адрес-алиас. Своих
экранов у администратора пока нет: в пробном режиме он не нужен.

**Ученик младше 18.** База требует почту родителя и до его согласия не
сохраняет прогресс в аккаунт. Письмо родителю отправляет сервер сайта,
которого пока нет, поэтому в пробном режиме такой ученик войти может,
а прогресс у него не сохраняется. Для тестовых учеников указывайте год
рождения взрослого.

**Новая редакция документов.** Дата редакции — в
`app/src/content/legal/operator.json`. Поменяли дату — нажмите «Сервер:
миграции»: кнопка опубликует редакцию в базе. Регистрация со старой
датой перестанет проходить, пока сайт не пересобран с новой.

## Что хранится в базе

Пароли сайт не хранит нигде: их хеширует служба входа (bcrypt), в
таблицах ниже пароля нет. Все таблицы — под правилами доступа (RLS).

| Таблица | Что это | Кто видит |
|---|---|---|
| `auth.users` (служебная) | почта, хеш пароля, даты подтверждения и входа, данные формы | только служба входа |
| `profiles` | роль, имя, класс школы, факты онбординга | сам человек; репетитор — своих учеников; ученик — своего репетитора |
| `consents` | журнал согласий: документ, редакция, время, IP | сам человек |
| `parent_consents` | ученик младше 18: год рождения, почта родителя, подтверждение | сам ученик |
| `kits` | коды комплектов печатных листов репетитора | сам репетитор |
| `user_storage` | прогресс из браузера, который человек разрешил перенести: ключ хранилища → значение | только сам человек (репетитор — нет) |
| `classes`, `class_members`, `tutor_students` | классы и связи «репетитор — ученик» | репетитор — свои; ученик — свой класс |
| `homework…`, `attempts`, `trainer_sessions`, `variant_…` | домашние задания, попытки, тренировки, онлайн-вариант — заработают на следующих этапах | по тем же правилам: своё и своих учеников |
| `vault.secrets` | список `allowed_emails` | никто снаружи |

Анониму открыты только справочники (номера заданий, прототипы банка,
даты редакций документов). Ни одной функции базы аноним вызвать не
может.

Удаление аккаунта (кнопка в кабинете) удаляет пользователя и всё, что
в нём сохранено, каскадом. Остаётся только запись о данном согласии с
отметкой об удалении: по закону она хранится три года. Данные в
браузере не трогаются.

## Перенос прогресса гостя

Гость пользуется сайтом без входа: прогресс лежит в браузере. При
первом входе в кабинет сайт спрашивает: «Перенести ваш прогресс с этого
устройства в кабинет?»

- «Да» — значения ключей уходят в таблицу `user_storage` как есть.
  Повторить перенос позже можно на вкладке «Профиль».
- «Нет» — в аккаунт ничего не уходит.
- В браузере в обоих случаях всё остаётся как было.

Что переносится, задаёт один список —
`app/src/lib/progressImport/registry.ts`. Сейчас в нём задание №8:
прогресс тренажёра по типам, опорные задачи и незаконченная
тренировка. Чтобы подключить №5, №7 или №12, в список добавляется одна
запись с ключами раздела; больше ничего менять не нужно. Проверка
`pnpm test:progress-import` следит, чтобы ключи в списке совпадали с
теми, что пишут разделы.

На этом этапе перенос — только запись в аккаунт. Чтение обратно на
другом устройстве (синхронизация) — этап 2.

## Отложено до настоящей регистрации учеников

Для пробы с вашими адресами это не блокер. Перед тем как пускать
учеников, нужно:

1. **Уведомление в Роскомнадзор** об обработке персональных данных —
   до первой регистрации (`LEGAL IP RU.md` §3).
2. **Письмо родителю** и подтверждение его согласия — нужен серверный
   код сайта (сессия С-3 в `CABINET_UX_SPEC.md`). До него ученики
   младше 18 прогресс не сохраняют.
3. **Окно «Документы обновлены»** при входе после новой редакции — тот
   же серверный код: согласие заново записывается с IP.
4. **Открыть регистрацию**: вместо списка адресов — код класса и
   ссылка-приглашение от репетитора (этап 3).
5. **Cookie httpOnly** для сессии — только со своим серверным кодом.
6. **Удалить тестовые данные**: кнопка «Сервер: тестовые данные»,
   режим «удалить».
