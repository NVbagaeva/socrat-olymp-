# Сервер по шагам: что купить и куда что вписать

Простая версия [SERVER.md](SERVER.md). Всё делается с телефона или
компьютера, в терминал заходить не нужно.

**Главное правило:** пароли, ключи, токены и IP-адрес **никому не
присылайте, в том числе мне в чат**. Они вписываются только в GitHub
(шаг 5). Я их оттуда не вижу — их берут сами кнопки.

Что будет у вас в конце:

| Что | Где | Зачем | Сколько стоит |
|---|---|---|---|
| Сервер | FirstVDS | на нём живут вход и кабинеты | 599 ₽ в месяц |
| Ящик `noreply@budetege.ru` | Яндекс 360 | отсюда уходят письма «Подтвердите почту» | по тарифу Яндекс 360 |
| Хранилище копий | Yandex Cloud | туда каждую ночь кладётся копия базы | копейки в месяц |

Сам сервер покупается **не в Яндексе**, а в FirstVDS: так дешевле, и
кнопки настроены под него. Яндекс нужен только для почты и для копий.

---

## Шаг 1. Купить сервер (FirstVDS) — 10 минут

1. Откройте [firstvds.ru → VDS](https://firstvds.ru/products/vds_vps_hosting).
2. Тариф **«Старт»**, вариант **NVMe** (2 ГБ памяти).
3. При заказе выберите:
   - **дата-центр:** Москва;
   - **операционная система:** **Ubuntu 24.04**;
   - **панель управления:** **без панели** (ispmanager не нужен);
   - дополнительные IP, автобэкап и прочие галочки — **не нужны**.
4. Оплатите **1 месяц**.
5. Придёт письмо. В нём два нужных значения:
   - **IP-адрес** (четыре числа через точку, например `1.2.3.4`);
   - **пароль root**.

   Письмо никому не пересылайте. Эти два значения понадобятся в шаге 5.

## Шаг 2. Почта noreply@budetege.ru (Яндекс 360) — 20 минут

С этого ящика сайт отправляет письма «Подтвердите почту» и «Сброс
пароля», а сервер — письма вам о проблемах.

> ⚠️ **Прежде чем начать.** Яндекс попросит поменять почтовые записи
> домена (MX). После этого **вся почта на адреса `…@budetege.ru` пойдёт в
> Яндекс**. Если у вас уже есть ящики на budetege.ru где-то ещё (например,
> у Timeweb) — остановитесь и напишите мне, решим, как сделать.

1. Откройте [360.yandex.ru/business](https://360.yandex.ru/business/) и
   войдите своим Яндекс ID.
2. Подключите организацию, выберите самый дешёвый тариф.
3. **Добавьте домен** `budetege.ru`.
4. Яндекс покажет записи, которые нужно добавить в DNS домена. Обычно это:
   - **TXT** — подтверждение, что домен ваш;
   - **MX** — куда приходит почта;
   - **TXT для SPF** — чтобы письма не попадали в спам;
   - **TXT для DKIM** — тоже против спама.

   Добавьте их там, где управляете доменом (скорее всего, в панели
   Timeweb → Домены → budetege.ru → DNS). Копируйте значения из Яндекса
   целиком, без пробелов по краям. Записи начинают работать от нескольких
   минут до суток.
5. Когда Яндекс покажет «Домен подтверждён», создайте сотрудника с ящиком
   **`noreply@budetege.ru`**.
6. Войдите в этот ящик (в отдельном окне или режиме инкогнито).
7. Создайте **пароль приложения**: [id.yandex.ru](https://id.yandex.ru) →
   **Безопасность** → **Пароли приложений** → **Почта** → придумайте имя,
   например «сервер» → **Создать**.
8. Яндекс покажет пароль **один раз**. Не закрывайте страницу, пока не
   вставите его в GitHub (шаг 5, секрет `SMTP_PASSWORD`).
   Это не пароль от ящика, а отдельный, только для отправки писем.

## Шаг 3. Хранилище копий (Yandex Cloud) — 15 минут

1. Откройте [console.yandex.cloud](https://console.yandex.cloud) и
   войдите тем же Яндекс ID.
2. Создайте **платёжный аккаунт**: понадобится банковская карта. Новым
   аккаунтам Яндекс обычно даёт стартовый грант.
3. Создайте **каталог** (folder) или используйте тот, что создан сам
   (обычно называется `default`).
4. Слева в меню: **Object Storage** → **Создать бакет**:
   - **имя:** `budetege-backups` (если занято — добавьте цифру, например
     `budetege-backups-1`, и запомните, какое получилось);
   - **доступ** на чтение, к списку объектов и к настройкам — везде
     **ограниченный**. Публичным бакет делать нельзя;
   - **класс хранилища:** стандартное;
   - **Создать бакет**.
5. Слева в меню: **Сервисные аккаунты** (или **Identity and Access
   Management → Сервисные аккаунты**) → **Создать сервисный аккаунт**:
   - **имя:** `budetege-backup`;
   - **роль:** `storage.editor`;
   - **Создать**.
6. Откройте созданный аккаунт `budetege-backup` → **Создать новый ключ**
   → **Создать статический ключ доступа** → **Создать**.
7. Яндекс покажет **идентификатор ключа** и **секретный ключ** —
   **один раз**. Не закрывайте окно, пока не вставите оба в GitHub
   (шаг 5: `S3_ACCESS_KEY_ID` и `S3_SECRET_ACCESS_KEY`).

## Шаг 4. Токен GitHub — 5 минут

Он нужен, чтобы кнопка «Подготовить сервер» сама сохранила созданные
ключи. Токен даёт право только записывать секреты этого репозитория и
живёт 7 дней.

1. На GitHub: ваша аватарка справа вверху → **Settings**.
2. В самом низу меню слева → **Developer settings**.
3. **Personal access tokens** → **Fine-grained tokens** → **Generate new
   token**.
4. Заполните:
   - **Token name:** `budetege-server`;
   - **Expiration:** 7 days;
   - **Repository access:** **Only select repositories** → выберите
     `socrat-olymp-`;
   - **Permissions** → **Repository permissions** → **Secrets** →
     **Read and write**. Больше ничего не трогайте.
5. **Generate token**. Токен показывается **один раз** — сразу вставьте
   его в секрет `GH_SECRETS_TOKEN` (шаг 5).

## Шаг 5. Вписать всё в GitHub — 10 минут

Откройте репозиторий `socrat-olymp-` → **Settings** → слева **Secrets and
variables** → **Actions**.

### Вкладка «Secrets» → кнопка «New repository secret»

Каждая строка — отдельный секрет. **Name** — левый столбец, буква в букву;
**Secret** — значение.

| Name | Что вставить | Откуда |
|---|---|---|
| `SERVER_HOST` | IP-адрес сервера | письмо FirstVDS, шаг 1 |
| `SERVER_ROOT_PASSWORD` | пароль root | письмо FirstVDS, шаг 1 |
| `SMTP_PASSWORD` | пароль приложения | Яндекс ID, шаг 2 |
| `S3_ACCESS_KEY_ID` | идентификатор ключа | Yandex Cloud, шаг 3 |
| `S3_SECRET_ACCESS_KEY` | секретный ключ | Yandex Cloud, шаг 3 |
| `GH_SECRETS_TOKEN` | токен | GitHub, шаг 4 |
| `ALERT_EMAIL` | ваша обычная почта | куда слать письма о проблемах |
| `ALLOWED_EMAILS` | ваша почта для входа на сайт | пока только ваш адрес; другие — через запятую |

Секреты `SERVER_SSH_KEY`, `SERVER_KNOWN_HOSTS`, `BACKUP_AGE_IDENTITY` и
`BACKUP_AGE_RECIPIENT` создавать **не надо**: их создаст кнопка сама. Когда
они появятся — **никогда их не удаляйте**: без них не попасть на сервер и
не расшифровать копии.

### Вкладка «Variables» → кнопка «New repository variable»

| Name | Value |
|---|---|
| `S3_BUCKET` | имя бакета из шага 3, например `budetege-backups` |

Остальное (`SMTP_USER`, `API_DOMAIN`, адреса сайта) уже подставлено по
умолчанию — трогать не нужно.

## Шаг 6. Написать мне

Напишите в чат: **«секреты заведены»**. Без паролей и IP.

Дальше я нажму кнопки по порядку: «Подготовить сервер» →
«Развернуть» → «Миграции» → «Копия сейчас» → «Проверить восстановление»
→ «Проверить здоровье» — и напишу, что получилось. После «Подготовить»
скажу, когда можно удалить `SERVER_ROOT_PASSWORD` и `GH_SECRETS_TOKEN`.

Вход на сайте после этого **ещё не включится** — это этап 2, по вашей
отдельной команде.

## Если что-то не получается

| Что случилось | Что делать |
|---|---|
| FirstVDS не предлагает Ubuntu 24.04 | Напишите мне, какие версии Ubuntu есть в списке. |
| Яндекс 360 пишет «домен не подтверждён» | Подождите час и нажмите «Проверить» ещё раз. Записи DNS иногда расходятся до суток. |
| На budetege.ru уже есть почта | Не меняйте MX, напишите мне. |
| Закрыли окно, а пароль/ключ не скопировали | Ничего страшного: создайте новый (пароль приложения или статический ключ) тем же способом, старый удалите. |
| Ошиблись в секрете GitHub | Нажмите на секрет → **Update** и вставьте заново. Посмотреть старое значение GitHub не даст — это нормально. |
| Не нашли пункт меню с таким названием | Яндекс и GitHub иногда переименовывают кнопки. Напишите, на каком шаге и что видите на экране, — подскажу. |
