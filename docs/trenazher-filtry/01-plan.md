## 2. Адаптеры «Собрать вариант» и конфиг генератора

- **Адаптеров `getRandomTask(filters, rng)` в коде нет.** «Собрать вариант» пока существует только как проект интерфейса `TaskEngine` в `docs/13-economics/02-design.md`, §8.4. Получить одну задачу сегодня можно по-разному в каждом разделе: `sobratZadachu` (№1, №11), `makeTask` (№2, №8, №9), `generate` (№13), загрузка по id из готового JSON (№6, №7, №10), вариант из пула (№4/5), `pickTasks` (№12, только целым набором).
- **Конфиг генератора подходит как конфиг фильтров.** `GenConfig` уже описывает темы → подтипы, уровни и источники; `config1`, `config2`, `config8`, `config9`, `config11`, `config12` строятся из тех же данных, что и тренажёры. У №3–7, №10 и №13 общего конфига ещё нет.

**Предложение:** ввести адаптер раздела, который один на генератор, тренажёр и будущий «Собрать вариант»:

```ts
interface RazdelZadachi {
  filtry: FiltrConfig;          // темы → подтипы, уровни, источники — то, что сейчас в GenConfig
  /** Все задачи, которые подходят под фильтр: ключ, подтип, уровень, источник. Конечный список. */
  spisok(f: Filtr): ZadachaRef[];
  /** Задача по ключу: условие, рисунок, проверка, подсказки, разбор. */
  zadacha(ref: ZadachaRef): Promise<ZadachaTrenazhera>;
  /** Похожая: тот же подтип, другие числа. */
  pohozhaya(ref: ZadachaRef, rng: Rng): ZadachaRef;
}
getRandomTask(f, rng) = случайная из spisok(f)   // общий код, один на все разделы
```

`GenConfig` разделяется на `FiltrConfig` (общая часть) и настройки листа; генератор продолжает работать как сейчас, только берёт фильтры из того же объекта. Дублей конфигов нет.

**Конечный список у генерируемых разделов** (№2, №8, №9, №12): счётчики на чипах должны быть честными, поэтому тренажёр берёт задачи из уже существующего банка seed (№2 и №8 — по 10 на прототип, №9 — 20, №12 — 748 задач наборов). «Похожая задача» и «Перерешать ошибки» дают свежий seed сверх банка.

**Старые режимы → новые фильтры:** «Отработка» → порядок «от простых к сложным»; «Смешанная» / «Вперемешку» → порядок «случайно»; «Повтор ошибок» → «Мои задачи: только с ошибками»; «Контроль» → «Без подсказок»; флажок «Показывать подсказки» → режим «С подсказками». Старые ссылки вида `/trenazher/<режим>/` открывают тренажёр с соответствующими фильтрами.

## 4. Архитектура

- `lib/trenazher/filtr.ts` — без React: состояние фильтра, чтение и запись в ссылку (`?t=12.A,12.B&ist=fipi&ur=2&n=10&rezh=podskazki&por=sluch&moi=oshibki`), счётчик и числа на чипах (каждый чип считается при остальных фильтрах), «Расширить фильтры» (снять последний добавленный), готовые наборы, сводка «№12 · параболы · ★★ · 10 задач».
- `lib/trenazher/statistika.ts` — «нерешённые / с ошибками» и прогресс на чипах «8/12» из существующих хранилищ разделов через адаптер; новых ключей нет. Чего не хватает: у №12 нет исходов по задачам — добавлю в `trainerProgress` поле `outcomes` (как в `progressStore`), у №10 хранилища нет — заведу на `createProgressStore`. №4/5 и №6 начнут писать неверные ответы.
- `components/filtry/` — общая панель: чипы типов, источник, звёзды, «Сколько», режим, порядок, «Мои задачи», строка активных фильтров с крестиками, «Сбросить», готовые наборы, нижняя шторка на телефоне (на основе `GenWindow`). Генератор переходит на те же источник, звёзды, шторку и строку активных фильтров; его «Состав» со степперами остаётся, потому что задаёт число задач каждого типа.
- `components/trenazher/` — один тренажёр на `TrainerSessionHost`: строка-сводка, лента номеров 1…N со статусами, карточка (условие в KaTeX, рисунок движком раздела, поле ответа, «Проверить», «Подсказка по шагам», «Пропустить», «Похожая задача»), таймер для режима «На время», итог с разбивкой по типам и ссылками на опорные задачи и теорию.
- **Плагины раздела:** поле ответа (число, дробь, единицы, выбор, таблица №13), подсказка (общий `HintStep`; у №9 свой формат переводится в него), рисунок, разбор. Раздел даёт только адаптер и плагины.
- **Сессии:** запись хранит фильтр и ключи задач (рецепт, без готовых SVG и разборов). Старые незавершённые сессии: где ключи совпадают (№11, №13, №12, №8, №2 — там уже рецепты «id + seed»), запись переводится в новый формат при входе; где нет — открывается прежним экраном до завершения, затем раздел уходит на новый. Свои хранилища №1, №9, №10 переводятся на общую оболочку и попадают в `LEGACY_SESSION_KEYS` после перевода записи.
- Последние фильтры раздела — `localStorage`, ключ `budetege:trenazher:<раздел>:filtr`.

## 6. Тесты

- `test:trenazher-filtry` (без браузера, все подключённые разделы): число на каждом чипе = длина `spisok` с этим чипом при остальных фильтрах; счётчик «Найдено N» = длина `spisok`; ссылка → фильтр → ссылка 1:1 (случайные 500 фильтров на раздел); «Расширить» всегда даёт непустой результат или пустой фильтр; «Только с ошибками» берёт ровно задачи с ошибками из подставленной статистики.
- Браузер: пауза и возобновление; старая сессия каждого раздела (записи-образцы прежних форматов) открывается и доходит до итога; нет горизонтальной прокрутки на 320, 375 и 390 px во всех состояниях; липкая кнопка «Начать» не закрывает содержимое.
