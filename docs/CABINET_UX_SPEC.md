**Разделы задания** — лента вкладок из конфига (`content/vkladki.ts`, `content/veroyatnost.ts`, `content/vychisleniya.ts`): О задании · Теория · Ключевые методы решения · Опорные задачи (прежнее имя — «Подготовительные задачи») · Тренажёр · Генератор, плюс кнопка-меню «Для репетиторов» в той же ленте.

**Тренажёр.** Конфигуратор: навык → режим (`Отработка` / `Смешанная` / `Повтор ошибок` / `Контроль`) → количество (5 / 10 / 20 / Все) → сложность → «Начать тренировку». Сессия собирается в браузере на свежем seed (seed — число-зерно, от которого детерминированно, то есть воспроизводимо, зависят все числа задачи). Экран задания: условие, чертёж, одно поле ответа, подсказка цепочкой шагов, разбор. Итог подхода (`TrainerResult`): верно / всего, процент, ошибок, решено с подсказкой, время, разбивка по типам заданий.

**Проверка ответа без сервера.** Общий модуль `lib/secret.ts`: в браузер уходит не ответ, а его отпечаток (fingerprint — короткая необратимая свёртка строки) с солью раздела и ключом задачи; введённое нормализуется и сверяется по отпечатку; разбор зашифрован тем же отпечатком и раскрывается по нажатию. Так устроены №3, №4, №5, №8 и опорные задачи №12 (`lib/prepSecret.ts`). Тренажёр №12 держит ответ в памяти вкладки (в состоянии React) и сравнивает функцией `sameNumber` — в разметку он тоже не попадает. Честная оговорка из кода: это защита от подглядывания в разметку и в исходник, а не от человека с отладчиком. Правило «правильные ответы никогда не попадают в DOM» уже соблюдается на всех открытых разделах.

**Прогресс в браузере** — только `localStorage` (хранилище браузера на одном устройстве). Ключи, найденные в коде:

| Ключ | Что хранит | Кто пишет |
|---|---|---|
| `budetege:trainer:v1` | счётчики тренажёра №12 по наборам (решено / верно / секунды), список идентификаторов задач с ошибкой | `lib/trainerProgress.ts` |
| `budetege:prep:v1` | номера решённых опорных задач №12 по навыкам | `lib/prepProgress.ts` |
| `budetege:theory:<подтема>` | идентификаторы дочитанных разделов теории (пока только у квадратичной) | `lib/theoryRead.ts` |
| `budetege:state` | число «изучено разделов» для линейной подтемы; стартовое значение — DEMO (6) | `state/AppState.tsx` |
| `budetege:z3:trainer:v1` | то же, что у №12, для стереометрии | `lib/zadanie3/progress.ts` |
| `budetege:veroyatnost-4:v2`, `-5:v2`, `-4-uznay:v2`, `-5-uznay:v2`, `-4:prep:v1`, `-5:prep:v1` | тренажёр, режим «Узнай метод» и опорные задачи №4 и №5, плюс исход каждой задачи (`right` / `wrong` / `revealed`) | `lib/progressStore.ts` |
| `budetege:vychisleniya-8:v1`, `-8:prep:v1` | то же для №8 | `lib/vychisleniya/progress.ts` |

Ни в одном ключе нет правильных ответов — только счётчики, секунды, идентификаторы задач и исходы. Фабрика `lib/progressStore.ts` и прослойка `lib/storage.ts` написаны так, чтобы «подмена хранилища на сервер не задела ни один компонент». Это готовая точка для переноса прогресса в базу.

**Статистика внутри тренажёров** (реальные данные из `localStorage`): `TrainerStats` (№12), `Solid3Stats` (№3), `ProgressMetody` (№4, №5), `Trenazher8Stats` (№8). Показатели: всего заданий, решено, верно, неверно, точность, среднее время, разбивка по типам, совет «Рекомендуем повторить» (тип с наименьшей точностью при ≥3 решённых), список ошибок, кнопка «Сбросить».

**«Повтор ошибок»** уже есть как режим тренажёра: берутся идентификаторы задач из списка ошибок, генерируются те же задачи на новых seed (`lib/trainerSession.ts`, `fromMistakes`). Задача уходит из списка, когда решена начисто.

**Генератор** (вкладка «Генератор», `GeneratorScreen`): вид работы (самостоятельная / домашняя / проверочная / контрольная / тренировочный вариант / своё название) + дата → навыки → количество, сложность, колонки, тема (цветная / чёрно-белая) → две ссылки: «Лист для ученика» (`pechat/?…`) и «Лист с ответами» (`pechat/otvety/?…`). Все параметры и seed — в адресе, поэтому один адрес всегда даёт один и тот же лист, а лист ученика и лист с ответами совпадают по задачам. Лист собирается в браузере и сразу отправляется в печать (сохранить как PDF). Оговорка: лист с ответами тоже собирается в браузере, и тот, у кого есть его адрес, увидит ответы — защита только в том, что с листа ученика ссылки на него нет.

**Материалы для репетиторов** — меню `TutorMenu` с карточками из конфига (у №12, №4, №5, №8): рабочая тетрадь и PDF-практикум ученических версий. PDF с ответами по правилу `lib/sheet/outputs.js` в репозиторий не попадают (`app/pdf-private/` в `.gitignore`), собираются в CI и забираются архивом.

**Старый сайт учителя** (корень репозитория) — рабочий прообраз «класса»:
- `classes.html` / `class.html?grade=N` — раздел класса 5–11 за кодом доступа. Код один на класс, проверяется в браузере: SHA-256 (хеш — необратимая свёртка) введённого кода сравнивается с `codeHash` из `data/classes.json`. Служебная страница `code.html` считает хеш для нового кода. **Это только прообраз интерфейса ввода кода.** Для платного доступа код проверяется исключительно на сервере: хеш в открытом файле подбирается перебором, а «открыто / закрыто» решает браузер, которому нельзя доверять (решение Натальи, п. 5 ответа на этап 0; совпадает с `PRODUCT BRIEF AND ROADMAP.md`, пакет А2).
- `data/classes/N.json` — домашние задания класса: название, тема, описание, дата выдачи, дедлайн (срок сдачи), заметка учителя; теория и рабочие файлы.
- `assets/js/deadlines.js` — статусы срока: «Сдано», «Просрочено на N дней», «Срок сегодня», «Завтра», «Осталось N дня», «До 8 сентября», «Без срока». Сортировка: сначала горящие. Эти формулировки и правило сортировки переиспользуются в кабинете.
- Отметка «Сделал» хранится в браузере (`socrat-hw-*`), учитель её не видит — так и написано на странице. «Сдать решение» — ссылка в Telegram или на почту.

## Этап 1. Путь ученика и путь учителя

Принцип для обоих путей: **в любой точке пользователь понимает свой следующий шаг**. Это обеспечивается тремя правилами:
1. На каждом экране один главный CTA (главная кнопка действия), он всегда ведёт к следующему этапу пути.
2. Главная кабинета всегда показывает «Что дальше»: ближайший срок, невыполненную работу или совет из статистики. Если ничего нет — честное пустое состояние с одной кнопкой.
3. Если пользователь застрял (не сделал шаг за отведённое время), система возвращает его сама: письмом (только при согласии на рассылку) или карточкой на главной.

Обозначения в колонке «Сервер»: **да** — без серверной части этап невозможен; **нет** — работает на статическом сайте уже сейчас; **нет / да** — работает без сервера, но результат виден только в этом браузере, а для учителя и других устройств нужен сервер.
