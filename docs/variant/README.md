# «Собрать вариант» — генератор варианта первой части (задания 1–13)

Маршрут `/variant/`. Один набор вариантов — три листа: ученику, учителю
и разбор для ученика (плюс «всё одним PDF»).

## Как устроено

```
app/src/lib/variant/
  types.ts        Variant, VariantTask, SectionAdapter, VariantConfig, VariantMeta
  build.ts        buildVariantSet(): партия по seed — параллельные варианты,
                  без повторов, замены, ослабление фильтров с пометками
  code.ts         код партии ⇄ настройки + seed + замены (Crockford base32)
  sections.ts     лёгкие описания разделов для экрана (adapters/zNN/info.ts)
  load.ts         динамическая загрузка адаптеров и данных банков
  session.ts      настройки по умолчанию, проверка сохранённых, buildSet()
  sheets.ts       три листа → описание для lib/sheet (buildDocument)
  handoff.ts      передача набора с экрана на вкладку печати (window.opener)
  adapters/zNN/   адаптер раздела: info.ts (подтипы, возможности) + index.ts
  data/zNN.ts     данные банка, собранные на сборке (без ответов)
app/src/app/variant/                  экран и страница печати
app/src/app/variant/dannye/zNN.json/  статичные JSON для data/zNN.ts
app/src/components/variant/           экран, предпросмотр, плашка-вход
```

**Один набор — три листа.** Набор (`VariantSet`) живёт в состоянии экрана.
Кнопки PDF открывают `/variant/pechat/?list=…&kod=…`, и вкладка печати берёт
тот же объект через `window.opener` — задачи она не генерирует. Если связи с
экраном нет (вкладку перезагрузили), набор собирается заново по коду: сборка
детерминирована. Если код собран другой версией генератора, лист об этом
предупреждает.

**Код варианта** — `SEED-СОСТАВ-ВЕРСИЯ[.Sподтипы][.Zзамены]`, например
`K7M2-407ZZ-4F`. Шапка работы (тип, дата, учитель) в код не входит.

**Лист ученика** — как КИМ: после каждого задания строка «Ответ: ____»,
бланка ответов в листе нет. Инструкция стандартная для типа работы. В
формате ЕГЭ и на пробном ЕГЭ она с переносом ответов в бланк ответов № 1,
в остальных работах — без бланка. Свою инструкцию учитель правит на экране.

**Сложность на листы не печатается** — ни у ученика, ни у учителя, ни в
разборе. Звёзд, «база/сложная», lucky/unlucky на листах нет. Сложность
видна только на экране: в фильтрах и в предпросмотре, рядом со значком
«заменить». Это проверяет `pnpm test:variant`. Листы генераторов
разделов 1–13 проверены так же, пометок уровня на них нет.

**Бланки ЕГЭ** в листы и в «Всё одним PDF» не попадают никогда — только
через блок «Бланки» (см. ниже).

**Лист ученика — 1–2 страницы на вариант.** Рисунки разделов на листе
мельче, чем на листах разделов. Если вариант всё же не уложился в две
страницы, лист сам перебирается в плотном режиме: кегль и рисунки чуть
мельче (`data-sheet-dense`, `variant-sheet.css`). На 60 проверенных
вариантах вышло ровно по 2 страницы.

**На листе ученика кода нет**: по коду на сайте собирается и лист с ответами.
Код печатается в таблице ответов учителя.

**Кабинет.** Чтобы сохранить работу или выдать её ученику, достаточно
хранить `config`, `seed` и `zameny` (или сам код).

## Рисунки на листах

Переключатель «Рисунки: крупные / обычные» стоит в фильтрах, по умолчанию
«крупные». Он хранится в шапке набора (`meta.figures`), как нумерация: на
задачи не влияет, в код не входит.

- **Крупные** — правила общего шаблона (`lib/sheet/figureRules.js`, см.
  `lib/sheet/README.md`). Клетчатые рисунки №2, №9 и №12 — клеткой 7 мм
  под условием, подписи не мельче 10 pt. Те же размеры на листе учителя
  и в разборе. Лист ученика длиннее двух страниц на вариант, и плотный
  режим на него не действует.
- **Обычные** — прежняя компактная раскладка (клетка 3 мм, рисунок
  справа), плотный режим при длине больше двух страниц на вариант.

Адаптеры №2, №9 и №12 рисуют рисунки в печатном профиле
(`withPrintFigures`); генерация задачи профиль не видит.

Условия всех адаптеров проходят правила `test:math-markup`: `test:variant`
выдаёт задачи каждого адаптера, пока банк не кончится (до 400). Это все
прототипы и по несколько задач каждого. Формула без слов внутри: KaTeX
в строгом режиме молчит.

## Бланки ЕГЭ

Блок «Бланки ЕГЭ-ГГГГ» — отдельный компонент
`components/blanki/BlankiEge.tsx`. На «Собрать вариант» он стоит рядом с
кнопками листов, на телефоне — под ними. Его можно поставить на любую
страницу, например в генератор второй части: `<BlankiEge defaultCopies={n} />`.

- Файлы — `app/public/blanki/ГГГГ/`, по одному на страницу:
  `registraciya.pdf`, `otvety-1.pdf`, `otvety-2-list-1.pdf`,
  `otvety-2-list-2.pdf`, `dop-otvety-2.pdf`.
- Страницы исходного PDF крупнее A4, при печати в масштабе 100 % их
  обрезало бы. Поэтому каждая поставлена на лист A4 целиком. Изображения
  не пересжаты: JPEG-потоки байт в байт как в оригинале.
- Бланк № 2 (лист 1 и 2), комплекты и копии бланка № 1 собираются в один
  PDF в браузере (`lib/blankiPdf.ts`, pdf-lib грузится по нажатию).
  Страница встраивается один раз, поэтому 3 копии весят как одна.
- Поле «Количество копий» по умолчанию равно числу вариантов.

**Новый год:**

1. `cd app && pnpm build:blanki ~/Бланки-ГГГГ.pdf ГГГГ` — страницы
   разложатся по `app/public/blanki/ГГГГ/`. Порядок страниц тот же:
   регистрация, № 1, № 2 лист 1, № 2 лист 2, дополнительный № 2.
2. Поменять `BLANKI_YEAR` в `app/src/content/blanki.ts`.

## Адаптер раздела

```ts
interface SectionAdapter {
  info: SectionInfo; // подтипы, capabilities: чего у раздела нет
  getRandomTask(filters: TaskFilters, rng: Rng): VariantTask | null;
}
```

- Фильтры: подтипы, источник (ФИПИ / свои / вперемешку), звёзды,
  `prototype` (параллельные варианты), `exclude` (уже взятые задачи).
- Нет задачи — `null`. Тогда ядро ослабляет фильтры по одному:
  прототип → звёзды → источник → подтипы → повтор. Каждое ослабление
  оставляет у задачи пометку в `fallbacks`.
- Поля, взятые из запасного варианта, тоже лежат в `fallbacks`. Экран
  показывает их с `?dev=1` (и всегда в `pnpm dev`).
- Решения строят рендереры разделов. Адаптер своей логики решения не пишет.

Проверка: `pnpm test:variant [номера] [--sets N] [--report]`. Она проверяет
детерминизм, поля задачи, отсутствие сырого TeX, отсутствие повторов,
параллельность, фильтры, код и замены.

| 13 | **из подсказок** + решение | полное | база ★ / сложная ★★★ | ФИПИ по прототипу, **номера нет** | — (таблица условия) |

Найдено попутно (в разделах, не в генераторе):

- №3: лист учителя раздела печатает ответы вида «216,0000000000001»
  (`pechat-dannye.ts` не округляет; P03-02, 47, 51, 61, 62, 66).
- №3: в некоторых условиях формулы набраны частично: «AD=4, AA₁=5»,
  «D1» вне `$…$`. Ещё P03-66 — `см³` внутри формулы.
- №5: в объяснениях шагов есть `$…$` (p5-04, p5-05, p5-12), а
  `answers.steps` в сборнике печатает их как есть. Нужно проверить
  `pnpm test:pdf-5`.
- №12: `quadraticSteps` в `lib/prep.ts` не находит `answerRule` у задач
  прототипов 12Q (ищет только в наборах опорных). В тренажёре разбор там,
  вероятно, кончается заглушкой «Ответ читается из формулы…».
- №7, №10: в адаптерах — строковые копии разметки `Razbor7.tsx` и
  `Razbor10.tsx`. Если меняются эти компоненты, копию нужно править
  вместе с ними. Лучше вынести в разделах строковый рендерер, который
  возьмут и компонент, и вариант.

Размер данных, которые грузятся по «Сформировать» (gzip):

- №3 — около 700 КБ;
- №4 — около 300 КБ;
- №5 — около 160 КБ;
- остальные — до 50 КБ.

Если №3 и №4 окажутся тяжёлыми, их можно разбить по подтипам.
