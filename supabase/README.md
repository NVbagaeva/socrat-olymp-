# Supabase: база и вход

Схема одна — схема кабинета. Её применяет на сервере кнопка «Сервер:
миграции» по списку `infra/lite/migrations.txt` (`docs/SERVER.md`).

- `migrations/` — миграции по порядку:
  - `…_soglasiya.sql` — согласия с правовыми документами
    (`docs/legal/README.md`);
  - `…_kabinet.sql` — роли, приглашения, классы, домашние задания,
    попытки, сессии тренажёра (`docs/kabinet-roli-dz.md`);
  - `…_variant_works.sql` — онлайн-вариант через кабинет;
  - `…_probnyy_vhod.sql` — пробный вход на этой же схеме: регистрация
    из браузера для адресов из списка, хук службы входа, администратор
    только с сервера, коды комплектов, перенос прогресса из браузера
    (`docs/AUTH.md`).
  - `…_dz.sql` — кабинет репетитора и домашние задания
    (`docs/kabinet-dz-8.md`);
  - `…_pochtovye_domeny.sql` — регистрация только с почтой российских
    сервисов;
  - `…_struktura_2027.sql` — ЕГЭ-2027: номер задания в базе — номер
    хранения, новому разделу — 21 (`docs/ege-2027-struktura-shag-0.md`).
- `seed/kabinet_katalog.sql` — каталог банка (номера заданий и
  прототипы). Собирается `pnpm build:kabinet-catalog`, применяется при
  каждом «Сервер: миграции».
- `tests/` — проверки на голом PostgreSQL (`pnpm test:soglasiya-sql`):
  согласия, кабинет, онлайн-вариант и правила доступа `rls.test.sql`
  (аноним, чужой ученик, чужой класс, репетитор без класса) на фоне
  прав своего сервера (`lite-defaults.sql`).
- `templates/` — тексты писем; на сервере их отдаёт Caddy.
- `config.toml` — настройки локального `supabase start`.

Тестовые ученики и «Тестовый класс» в миграции не входят: их создаёт
отдельная кнопка «Сервер: тестовые данные» (`infra/lite/bin/seed.sh`).

Секретов в этой папке нет и быть не должно: список разрешённых адресов
приходит из GitHub Secrets (`ALLOWED_EMAILS`), ключи создаются на
сервере.
