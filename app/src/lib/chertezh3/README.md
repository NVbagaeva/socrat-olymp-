# Чертежи задания №3

Сценарий (JSON) → сцена → кадр → SVG. Видимость, проекция и
раскладка подписей — общее ядро `lib/stereo` (на нём же №15).

| Файл | Что делает |
|---|---|
| `scenariy.ts` | формат сценария: тело, имена, ракурс, точки, данные условия, элементы с id, проверки |
| `geometriya.ts` | тела: куб, параллелепипед, правильная и прямая призма (3, 4, 6), правильная и произвольная пирамида, тетраэдр, составной многогранник (объединение и вычитание блоков по сетке) |
| `postroit.ts` | сценарий в пространстве: точки, элементы, тело ядра |
| `kadr.ts` | кадр при ракурсе: видимость элементов, подписи, подсветка шага |
| `svg.ts` | кадр строкой SVG: лист, предпросмотр, первый кадр |
| `vid.ts` | выбор вида: ракурс из набора KAMERY и сжатие высоты по метрикам `lib/stereo/metriki.ts` |
| `validator.ts` | проверка сценария |
| `obolochka.ts` | сечение плоскостью и выпуклая оболочка — для сборщиков |

Сценарии банка собирает `lib/zadanie3/chertezhi`: разбор текста
условия (`razbor.ts`), подбор размеров по данным условия и элементы
условия (`sborka.ts`), вспомогательные построения и ссылки шагов по
прототипам (`annotacii.ts`). Список «на проверку» —
`spisokNaProverku()`, он же на странице `/styleguide/chertezhi-3/`
(только в `pnpm dev` или с `GALEREYA=1`).

## Вид чертежа

Ракурс не задаётся руками: `chertezhVarianta` (lib/zadanie3/chertezhi)
перебирает ракурсы `KAMERY` от школьного (24°/24°) и берёт первый, при
котором чертёж читается на бумаге (метрики — `lib/stereo/metriki.ts`):
вершины не ближе 8 % размера фигуры, отрезки не сливаются (угол ≥ 12°
или 3 мм), вершина не ближе 2 мм к чужому отрезку, проекция основания
не ниже 25 % ширины, высота рисунка к ширине 0,8–1,4. Пропорции держит
вертикальный масштаб `szhatie` (сжатие до ×0,34, у плоского тела
вытягивание до ×2,6): кадр рисует образ S·p, S = diag(1, 1, sz), а
видимость считает по самой сцене с камерой S⁻¹k — это то же самое.
Ракурс и сжатие уходят в сценарий; интерактив начинает вращение с них.

## Видимость и оформление

Видимость — только расчётом ядра (`lib/stereo/vidimost.ts`): рёбра
выпуклого тела — правилом граней, остальные отрезки режутся в точках
пересечения с контурами лицевых граней и проколов, каждый кусок —
лучом из середины. Ручных пометок «видно / не видно» в сценариях нет.

На бумаге (`svg.ts`, `OFORMLENIE`): видимые линии 1,35 pt, невидимые
0,9 pt штрихом 4/3 pt, заливка выделенной фигуры 0,12 (подсвеченной —
0,15), подписи шрифтом KaTeX: имена курсивом KaTeX_Math, индекс 70 %
ниже строки прямыми цифрами, числа KaTeX_Main не жирно, кегль ≥ 10 pt.
Толщины заданы в pt через ширину рисунка на бумаге (`pechatMm`), лист
пересчитывает их под итоговую ширину (`data-line-pt`, sheet/figureRules.js).

Автотест — `pnpm test:stereo-kachestvo`: независимая проверка лучом
каждого куска линии, метрики вида на банке и 50 случайных наборах
параметров на шаблон, подписи, оформление.

## Роли

- `uslovie` — названо в условии (искомая диагональ, прямые угла,
  сечение, точка «O — центр основания»): видно ученику.
- `vspom` — построение решения (высота, апофема, треугольник): только
  с переключателем «Вспомогательные построения», на листе учителя
  и при подсветке шага.
- Данные условия (`dannye`) подписываются всегда; валидатор
  требует, чтобы число на чертеже было в тексте условия.

## Масштаб

Размеры тела — истинные, по данным условия (валидатор сверяет каждое
данное). Тело с крайними пропорциями (больше 3,2 : 1) рисуется не в
масштабе, как в учебнике: длинное измерение сжато до 2,6 : 1, подписи —
числа условия; такие варианты в списке «на проверку».

## Ответ в бандле

По размерам тела иногда виден ответ (высота пирамиды). Поэтому
сценарий в пуле тренажёра и в данных листа закрыт тем же отпечатком,
что и разбор (`lib/zadanie3/secret.ts`), и открывается при показе.

## Следующие этапы: тела вращения и комбинации

Интерфейс уже в ядре (`lib/stereo/vrashchenie.ts`, `lib/stereo/tela.ts`):

1. **Тела** — `TeloVrashcheniya` реализует `RisuemoeTelo`: цилиндр,
   конус, усечённый конус, шар. Для заслонения — выпуклые части
   (призма/пирамида с 48 гранями, многогранник для шара); свои линии
   считаются точно.
2. **Основания** — `Okruzhnost` (центр и два радиус-вектора), в
   проекции — эллипс. Видимая и невидимая половины разделены точками
   касания контурных образующих: `polovinyOkruzhnosti(o, k)` уже есть
   и проверяется тестом. Дуги — `DugaEllipsa`, кадр рисует их путём
   SVG (сплошная и штриховая половины).
3. **Контурные образующие** — отрезки, зависящие от ракурса:
   `kontur(kam)` на каждом кадре; у конуса — касательные из вершины
   к эллипсу основания.
4. **Сценарий** — новые виды тела `cilindr`, `konus`, `shar`;
   элементы `radius`, `obrazuyushchaya`, `osevoe-sechenie`. Валидатор
   сейчас такие тела отклоняет («следующий этап»).
5. **Комбинации** — несколько тел в сцене (`tela: TeloScenariya[]`),
   внешнее помечается `prozrachnoe`: его части не заслоняют линии
   внутреннего тела, свои невидимые линии оно прячет само. Линии
   каждого тела проверяются против частей остальных — `linii(kam,
   chuzhie)` уже принимает чужие части.
6. **Банк** — разделы IV–VIII: разбор условий тел вращения, таблица
   прототипов, перенос чертежей с движка `lib/solid`.
