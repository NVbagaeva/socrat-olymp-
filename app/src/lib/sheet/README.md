# Шаблон печатного листа

Живёт в `app/src/lib/sheet/` — логика без React, поэтому её место
рядом с движком графиков в `src/lib`. Модули — обычные ES-модули:
их собирает Next.js и запускает Node в служебных скриптах.

Лист про предмет ничего не знает. Он получает готовые куски
разметки и раскладывает их по A4: шапка, название, рамка
«Повторяем», заголовки блоков, карточки задач, подвал. Поэтому
одним и тем же шаблоном печатаются сборники задания №12,
варианты генератора и задание №3 с чертежами стереометрии.

## Слои

| Файл | Что делает |
|---|---|
| `theme.css` | две темы: цветная и ч/б для печати. Только значения токенов |
| `sheet.css` | вёрстка листа. Ни одного цвета и ни одного кегля значением |
| `sheet.js` | сборка документа: `buildDocument(spec, assets) -> строка HTML` |
| `paginate.js` | разбиение потока на страницы. Работает в браузере |
| `marks.js` | логотип, иконки соцсетей, декоративные дуги — инлайновым SVG |
| `typography.js` | неразрывные пробелы, ёлочки, длинное тире |
| `outputs.js` | куда ложится готовый файл: с ответами или без |

Слова листа здесь не лежат: тексты сборника №12 —
в `src/content/sheet12.js`.

## Две темы

Тема выбирается одним полем `spec.theme`: `'color'` или `'print'`.
Компоненты листа своих цветов не знают — всё приходит токенами
из `theme.css`.

Ч/б тема — не серая копия цветной, а отдельный набор значений:
заливок нет ни у карточек, ни у рамки «Повторяем», ни у плашек,
ни у фона; декоративные дуги сняты; в ходу только чёрный, белый
и два серых. То, что в цвете выделено цветом, в ч/б выделено
толщиной линии: `--graph-curve-a-width` и `--graph-curve-b-width`
делают вторую прямую толще первой, потому что цвета для неё нет.

Логотип монохромной версией не дублируется: он нарисован
токенами и в ч/б теме выходит белым квадратом с чёрным контуром.

## Файл с ответами не лежит в репозитории

Правило жёсткое и касается **любой** сборки листа — сборника №12,
генератора вариантов, задания №3.

Репозиторий публичный, и всё, что попало под версионный контроль,
видно всякому. Из `app/public` файл вдобавок отдаётся сайтом
по прямому адресу: ученику достаточно угадать имя. Поэтому:

| Что в файле | Куда ложится | Как попадает к человеку |
|---|---|---|
| нет ответов | `app/public/materials/…` | отдаёт сайт |
| есть ответы или решения | `app/pdf-private/…` | архив со страницы запуска CI |

Своих путей сборки не придумывают — спрашивают `outputs.js`:

```js
const where = outputs.target(APP, {
  name: 'zadanie-12-…-uchitel',
  section: 'zadanie-12',
  withAnswers: true,              // ← отсюда и берётся папка
});
outputs.assertSafe(where.file, true);   // бросит, если путь ведёт в public
```

`app/pdf-private/` закрыта `.gitignore`. Папка намеренно без точки
в начале: скрытые файлы `actions/upload-artifact` по умолчанию
пропускает, и архив вышел бы пустым.

Забыть правило не даёт `pnpm test:pdf-12`: он спрашивает у git,
не попал ли под версионный контроль файл с ответами в имени, —
и валит сборку, если попал. Смотрит именно git, а не диск: рядом
такой файл лежать может, его только что собрали.

## Разбиение на страницы

Считать высоту карточки заранее нельзя: она зависит от шрифта,
длины условия и размера чертежа. Поэтому страницы набираются
обмером в браузере, уже после `document.fonts.ready`.

Правила набора:

1. Кусок потока неделим — **задача не разрывается никогда**.
2. Кусок с `data-keep-with-next` не остаётся последним на
   странице: заголовок блока уезжает вниз вместе с первой задачей.
3. Кусок с `data-page-break` начинает новую страницу — так
   раздел «Ответы» встаёт с чистого листа.

Пагинатор объявляет отчёт в `window.sheetPagination`:
сколько вышло страниц, сколько задач встало на лист и не
попался ли кусок выше страницы. Сборка сверяет эти числа
с банком и падает, если они разошлись: молча выпустить PDF
с потерянной задачей нельзя.

## Размер чертежа

Чертёж масштабируется **по клетке**, а не по ширине карточки:
у движка клетка всегда 34 единицы `viewBox`, поэтому
`--sheet-cell` задаёт её физический размер, и клетка выходит
одинаковой на всех задачах. Окна у задач разные (±5 и ±8),
значит и чертежи разного размера — зато точки читаются
одинаково уверенно.

Значение задаётся полем `spec.cell` в миллиметрах. Сейчас
в сборнике №12: 3,4 мм в одну колонку, 3,0 мм в две.

## Как напечатать

Печать — не дело шаблона: он отдаёт HTML, который открывается
и в браузере, и на телефоне. PDF из этого HTML делает
`scripts/lib/sheet-render.mjs` через headless-Chromium.

```bash
pnpm build:pdf-12-sample   # образец: первый блок, обе темы, обе раскладки
pnpm build:pdf-12          # весь сборник
```

Скрипту нужен Playwright — он объявлен в `devDependencies`:

```bash
pnpm install
pnpm exec playwright install chromium
```

Ставить ничего не хочется — та же сборка есть в GitHub Actions:
вкладка **Actions**, workflow **PDF 12**, кнопка **Run workflow**.
Готовые файлы уезжают архивом на страницу запуска.

Там же собирается и `pnpm-lock.yaml`: playwright добавляли в среде
без доступа к реестру npm, поэтому lock-файл обновляется первым
шагом этого workflow и коммитится обратно в ветку. **Пока этот шаг
не прошёл, `check.yml` и `deploy.yml` будут падать** на
`pnpm install --frozen-lockfile`: pnpm не обновляет lock-файл,
а отказывается ставить.

## Формулы

Формула в разметке живёт тем же способом, что и на сайте:
`<span class="math" data-tex="…">`. Внутри лежит запасной набор
из `graph/math.js` — курсивные переменные и дроби столбиком, —
поэтому лист читается и без KaTeX. Когда KaTeX доступен,
`graph/katex-upgrade.js` заменяет разметку его вёрсткой.
