# Движок графиков, задание №12

Живёт в `app/src/lib/graph/` — это логика без React, поэтому её место
рядом с `fonts.ts` в `src/lib`. Модули — обычные ES-модули: их собирает
Next.js и запускает Node в служебных скриптах.

## Слои

| `generate-quadratic.js` | кандидаты, правила ответа, варианты формулы с пояснениями и сцена для задач о параболе |

(прототипы ФИПИ). Ответы — в `data/answers.json`, разделами, которые
нигде не складываются.

`answers.json` намеренно не импортируется в `data/index.js`: в клиентском
бандле ему не место, читать его должен сервер.

`app/scripts/build-graph-answers.mjs`.

## Парабола

Обозначения на всю подтему: `y = ax² + bx + c`, вершина `(m; n)`, формы
записи — общая, через вершину `a(x − m)² + n` и через нули
`a(x − x₁)(x − x₂)`. Набор с полем `family: 'quadratic'` собирается
модулем `generate-quadratic.js`; перебор с возвратом, состав набора
и файл ответов у семейств общие.

Правила читаемости (`families/quadratic.js`, `RULES`): `|a|` от 1/4
до 3; окно квадратное, от ±5 до ±8, берётся первое, в котором вершина
стоит не ближе клетки к рамке и по каждую сторону от неё ветвь
проходит хотя бы через один узел сетки строго внутри окна. Вершина —
на целых или полуцелых координатах; узлы сетки на ветвях при полуцелой
вершине есть только у `a = ±2` с полуцелыми обеими координатами и у
`a = ±0,5` с полуцелой ординатой. Всё, что читается с чертежа или
идёт в ответ, — целое или конечная десятичная дробь: иррациональные
корни и трети бракуются.

Пересечения: `intersection.visible: 'one'` — на чертеже одна
очевидная точка, в узле сетки и отмеченная; вторая не читается
с чертежа, и ответ получается решением уравнения. Где она —
`intersection.hidden`: `'offscreen'` (по умолчанию) — за рамкой
с запасом, вторая кривая проводится через две целые точки первой
параболы; `'fraction'` (только с прямой) — внутри окна, но не в узле:
прямая идёт через очевидную точку под читаемым наклоном, спрошенная
координата второй точки нецелая, обе — не длиннее двух знаков после
запятой. `'both'` — обе точки целые и в окне. Полный список
ограничений задачи — в шапке `generate-quadratic.js`.

Варианты формулы (`equation-choice`): верный и пять неверных, каждый
со своей ошибкой — знак `a`, величина `a`, `c`, абсцисса вершины,
ордината вершины, нули — и пояснением, привязанным к чертежу.

Разбор задачи о параболе строит `solution-quadratic.js`: семь шагов,
из которых показываются только нужные для ответа, остальные — в
свёрнутом блоке под ответом. Перевод разметки разбора в простой текст
живёт в `scripts/lib/quadratic-solution-text.mjs` и один на отчёты и
на проверку: формулы вынимаются в метки до удаления тегов, иначе знак
«меньше» уносит с собой хвост строки.

Проверка генератора на девяти наборах подтемы:
`pnpm test:graph-quadratic` — наборы берутся из `data/prep/12q/`,
правила проверки лежат в `scripts/lib/graph-quadratic-checks.mjs`,
и те же правила зовёт `validate:graph` для всех наборов семейства
из `data/`. Среди правил — проверка разборов: в каждом шаге формулы
закрыты, следов разметки не осталось, ответ стоит ровно один и набран
типографским минусом.

## Решения в листе ответов учителя

Раздел «Решения» листа учителя (генератор и сборник PDF) строит
`solution-teacher.js` прямо из `task.meta`: точных дробей
коэффициентов, отмеченных точек и окна чертежа. Разбор для ученика
(`solution.js`, `solution-quadratic.js`) не используется и не меняется.

В задачах с двумя функциями шаги идут так: f(x) по точкам с рисунка →
g(x) по точкам → f(x) = g(x) → стандартный вид (с умножением на общий
знаменатель и делением на общий множитель) → дискриминант и оба корня,
рядом — Виета → выбор корня (известный — абсцисса отмеченной точки) →
ордината, если спрашивают её → ответ. Нецелые коэффициенты пишутся
обыкновенной дробью; ответ — как в ключе.

Вместе с шагами модуль отдаёт `check`: найденные коэффициенты, взятые
точки, корни и ответ. По нему `pnpm test:teacher-solutions` сверяет
каждое решение с движком на серии seed: коэффициенты равны точным,
точки лежат на графиках, корни дают f(x) = g(x), ответ совпадает
с ключом, в формулах нет «+ −» и двойных скобок, KaTeX их принимает.
`--print 12Q.H 12.D` печатает тексты решений.

## Угловой коэффициент: только треугольник и тангенс

Методика проекта: k находится как `k = tg α`, где α — угол между прямой
и положительным направлением оси Ox. По двум точкам прямой в узлах
сетки строится прямоугольный треугольник ПОД прямой: отрезок между
точками — гипотенуза, катеты параллельны осям, длины катетов в клетках.
Возрастающая прямая — `tg α = верт. : гориз.`, угол α при левой точке;
убывающая — острый угол при правой точке равен `180° − α`,
`tg α = −tg(180° − α)`; параллельная Ox — `α = 0°`, `k = tg 0° = 0`.
Точки в тексте всегда называются слева направо.

Формулу через разность координат (Δy : Δx) не используем нигде:
ни в листе учителя, ни в разборах, ни в подсказках тренажёра, ни
в опорных задачах. Теория линейной функции, когда её будут наполнять,
объясняет k только этим способом.

Треугольник подсказывает ответ, поэтому на чертеже он рисуется только
по явной просьбе сцены: фигуры с пометкой `slope` рендерер выводит лишь
при `showSlopeTriangle: true`, по умолчанию их нет. Сцену с треугольником
собирает `slope-figure.js`, и берут её только три места: лист ответов
учителя, подсказка тренажёра (с шага «Построй треугольник», длины катетов —
со следующего шага) и разбор опорной задачи. На чертежах условий,
в листах ученика и на исходном чертеже тренажёра треугольника нет —
это сверяет `pnpm test:slope-visibility`. Новые разделы (гипербола
и другие) ученику его не покажут, пока сами не попросят.

Геометрию и тексты строит один модуль — `slope.js`: им пользуются
`solution-teacher.js`, `solution.js`, `solution-quadratic.js`
и `lib/trainer.ts`. Проверки: `pnpm test:teacher-solutions`
(треугольник под прямой, катеты положительные, знак и k совпадают
с ключом, порядок точек) и `pnpm test:trainer-slope` (цепочки подсказок).

План по гиперболе (ветка `claude/hyperbola-l7pcmz`, после её слияния —
отдельными PR): разбор 12R.G и 12R.H перевести на `slope.js`
(коэффициент прямой там — `a = tg α`), и лист учителя должен строить
решения для всех наборов 12R так же полно, как для прямой и параболы.

## Пара прямых: ключи задач 12.C и 12.D

У задач с двумя прямыми (`constraints.lines`) точка пересечения
описывается ключом `intersection`. Кроме давних `inside`, `decimals`,
`axis`, `marginCells`, `offscreenMin` и `answerKind` есть два ключа,
которые появились вместе с задачами уровня «Базовая» 12.C-21…24
и 12.D-21…24:

- `intersection.askedOffscreen: true` — за окном должна лежать именно
  спрашиваемая координата (`axis`), не ближе `askedOffscreenMin`
  клеток к рамке (по умолчанию одна). Без него «за кадром» означает
  точку целиком: она может уйти вверх, а её абсцисса — остаться
  внутри окна и читаться на глаз. Проверяет `validate-graph.mjs`.
- `constraints.varyBySeed: true` — порядок кандидатов задаётся seed,
  а не оценкой читаемости чертежа. Иначе задача с закреплёнными
  наклонами обеих прямых даёт один и тот же чертёж при любом seed.
  Правила читаемости (две целые точки, длина видимой части,
  различимость наклонов) действуют по-прежнему.

## KaTeX

Формула в разметке живёт одним способом: `<span class="math" data-tex="…">`.
Внутри лежит исходная запись — её видно, только пока KaTeX не отработал.

KaTeX — обычная зависимость проекта:

```bash
pnpm add katex
```

Подключение — стандартным импортом:

```ts
import katex from 'katex';
import 'katex/dist/katex.min.css';
```

`katex-upgrade.js` получает экземпляр аргументом и ничего не импортирует,
поэтому одна и та же замена разметки работает и на странице проекта,
и в служебном коде. Никакого CDN и никакой копии библиотеки в репозитории.

Подписи на самом чертеже и на тригонометрической окружности набираются
средствами `math.js`: чертёж — это SVG, KaTeX верстает HTML и внутрь
SVG не встраивается.
