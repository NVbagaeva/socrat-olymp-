# Движок графиков, задание №12

Живёт в `app/src/lib/graph/` — это логика без React, поэтому её место
рядом с `fonts.ts` в `src/lib`. Модули — обычные ES-модули: их собирает
Next.js и запускает Node в служебных скриптах.

## Слои

| Файл | Что делает |
|---|---|
| `renderer.js` | чертёж: `renderGraph(scene) -> строка SVG`. Без зависимостей и предметной математики |
| `families/line.js` | семейство «прямая»: точные дроби, целые точки, окно, различимость наклонов |
| `triangle.js` | треугольник наклона: вершина прямого угла, катеты, дуга, зона подписи |
| `solution.js` | разбор из пяти шагов: структура шагов и блоков, без DOM |
| `animate.js` | показ разбора по шагам поверх готового SVG |
| `math.js` | набор формул: курсивные переменные, дроби, `data-tex` для KaTeX |
| `katex.js` | KaTeX в приложении: обычный импорт пакета |
| `katex-upgrade.js` | подстановка вёрстки KaTeX в готовую разметку |
| `preview-ui.js` | служебная страница контроля: монтируется в любой контейнер |
| `data/index.js` | наборы задач статическим импортом |
| `generate.js` | сборка варианта: `generate(id, seed)`, `analysis(id, seed)` |

Данные — в `data/prep/12/` (подготовка) и `data/prototypes/12/`
(прототипы ФИПИ). Ответы — в `data/answers.json`, разделами, которые
нигде не складываются.

`answers.json` намеренно не импортируется в `data/index.js`: в клиентском
бандле ему не место, читать его должен сервер.

Проверка правил — `app/scripts/validate-graph.mjs`, сборка ответов —
`app/scripts/build-graph-answers.mjs`.

## Команды

```bash
pnpm validate:graph        # проверка; код возврата 1 при нарушении
pnpm build:graph-answers   # пересобрать answers.json
pnpm dev                   # затем открыть /styleguide/graph-12
```

## Страница визуального контроля

`src/app/styleguide/graph-12/page.tsx` — тонкая обёртка: берёт наборы
статическим импортом, KaTeX — обычной зависимостью, и монтирует
`mountPreview` из `preview-ui.js`. Сама страница про React ничего
не знает, поэтому её можно смонтировать и в обычном HTML.

## KaTeX

Формула в разметке живёт одним способом: `<span class="math" data-tex="…">`.
Внутри лежит исходная запись — её видно, только пока KaTeX не отработал.

KaTeX — обычная зависимость проекта:

```bash
pnpm add katex
```

Подключение — стандартным импортом:

```ts
import katex from 'katex';
import 'katex/dist/katex.min.css';
```

`katex-upgrade.js` получает экземпляр аргументом и ничего не импортирует,
поэтому одна и та же замена разметки работает и на странице проекта,
и в служебном коде. Никакого CDN и никакой копии библиотеки в репозитории.

Подписи на самом чертеже и на тригонометрической окружности набираются
средствами `math.js`: чертёж — это SVG, KaTeX верстает HTML и внутрь
SVG не встраивается.
