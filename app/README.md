# Будет на ЕГЭ — приложение

Next.js 15 (App Router) + React 19 + TypeScript в строгом режиме + Tailwind CSS 4.
Сборка статическая (`output: 'export'`), деплой на обычный хостинг.
Существующий сайт в корне репозитория живёт отдельно и этой папкой не затрагивается.

## Запуск

```bash
cd app
pnpm install
pnpm dev
```

Откройте http://localhost:3000/styleguide — витрина дизайн-системы.

## Команды

| Команда          | Что делает                      |
| ---------------- | ------------------------------- |
| `pnpm dev`       | локальный сервер разработки     |
| `pnpm build`     | статическая сборка в `app/out/` |
| `pnpm lint`      | ESLint                          |
| `pnpm typecheck` | `tsc --noEmit`                  |
| `pnpm format`    | Prettier                        |

Готовую сборку можно посмотреть локально: `pnpm build && npx serve out`.

## Правила дизайн-системы

1. Компоненты используют **только семантические переменные** (`--color-primary`).
   Примитивы (`--blue-600`) и хексы (`#1F5FD0`) в компонентах запрещены.
2. Примитивы намеренно не выведены в `@theme`: утилиты вида `bg-blue-600`
   не существуют, как и `text-2xl` — размеры текста задают классы `t-*`.
3. Брейкпоинты ровно три: `md` 768, `lg` 1024, `xl` 1280.
4. Шаг сетки 4px: `p-1` = 4px, `p-4` = 16px, `p-6` = 24px.

## Осознанные отличия от design-reference

Дизайн утверждён и переносится значение в значение. Места, где перенос
всё же отличается от эталонной вёрстки, — согласованы отдельно.
Это не недоделки: возвращать «как было» не нужно.

1. **`.pbar__fill` получил `display: block`.** В эталоне заливка — инлайновый
   `<span>`, поэтому `width` и `height` на нём не работали и прогресс-бары
   не заливались вообще. Баг эталона.
2. **`.field__msg` — блочный `<p>`, а не инлайновый `<span>`.** В эталоне
   объявленный `margin-top: 8px` отбрасывался по той же причине.
   Поле с сообщением на 4px выше, чем в эталоне. Баг эталона.
3. **Сайдбар сворачивается.** В вёрстке эталона он всегда 240px, но подпись
   под оболочкой говорит «240px → 72px на планшете → нижняя навигация
   на мобильном». Верна подпись: до 1024 — 72px, до 768 — скрыт,
   навигацию берёт BottomNavigation.
4. **`svg { display: block }` в сбросе.** Убирает свисание строки под
   инлайновым SVG. Заметно в одном месте: третий макет телефона
   на витрине на 6px короче эталонного.
5. **Логотип в шапке получил `flex: none`.** Без него иконка сжималась
   в прямоугольник, когда шапке не хватало ширины. Баг эталона.
6. **Меню в шапке прячется на 768px, а не на 760px.** На эталонном пороге
   при 761–768px шапка не помещалась и страница ехала вбок. Остальные
   правила лендинга остались на пороге 760px.
7. **`minmax(0, 1fr)` вместо `1fr`** в сетках `.hero__grid` и `.split`
   ниже 1024px. С `1fr` колонка не может стать уже своего содержимого,
   и на узком экране страница ехала вбок.
8. **Кнопка «Открыть по-настоящему»** в разделе «Состояния». В эталоне
   модалка нарисована статичной панелью, и проверить на ней перехват
   фокуса, Esc и возврат фокуса нельзя.

## Шапка на узких экранах

Ниже 414px шапка сворачивается: остаются логотип и кнопка
«Начать бесплатно» — слово «бесплатно» работает на конверсию
и не сокращается. Пункты навигации и «Войти» уходят в бургер-меню
(`SiteMenu`), «Войти» отделено в нём линией.

Панель выносится в `document.body` через портал. Внутри шапки она
работать не может: у `.site-head` есть `backdrop-filter`, а он делает
элемент содержащим блоком для `position: fixed` — панель ужалась бы
до размеров шапки.

Длительности лежат в токенах: `--dur-menu` 200ms на превращение иконки
и выезд панели, `--dur-menu-stagger` 35ms — шаг каскада пунктов.
Фон панели сплошной, без `backdrop-filter`: размытие тормозит на слабых
телефонах. При `prefers-reduced-motion` всё появляется мгновенно.

## Изображения героя

Исходники лежат в `public/hero/`: `hero-desktop.png` 1672×941
и `hero-mobile.png` 1122×1402, оба с прозрачным фоном.

AVIF и WebP собираются из них командой:

```bash
pnpm build:hero
```

Качество подбирается вниз, пока файл не уложится в бюджет:
AVIF до 120 КБ, WebP до 200 КБ. После конвертации проверяется,
что прозрачность сохранилась и по контуру не появилось светлой
или тёмной каймы. Сам детектор каймы проверяется отдельно:

```bash
node scripts/check-alpha-detector.mjs
```

Он подсовывает заведомо испорченные файлы — со светлым ореолом,
с тёмной обводкой и с потерянной прозрачностью — и убеждается,
что все три ловятся, а чистая копия проходит.

`next build` этот скрипт не запускает: AVIF и WebP коммитятся
вместе с исходниками и попадают в экспорт как есть.

**Исходники не растягиваются выше половины натуральной ширины** —
836px для десктопного и 561px для мобильного. На экранах
с удвоенной плотностью это отрисовка пиксель-в-пиксель; выше
стекло замыливается. Пределы заданы в `landing.css` классом
`.hero__art`. Если по макету понадобится больше — не растягивать,
а пересобирать композицию секции.

## Цифры по объёму банка заданий

На главной странице нет и не должно быть конкретных цифр по объёму банка:
число «318 прототипов» не выверено. Убраны и сам факт в шапке страницы,
и колонка со счётчиками по каждому направлению — в сумме она давала то же
число. Поля для них оставлены закомментированными в `src/content/landing.ts`
(`bank.totalPrototypes` и `Direction.count`): когда объём посчитают,
возвращается правкой в одном файле.

## Шрифт

Inter берётся из пакета `@fontsource/inter`. Он поставляется отдельными файлами
на каждый юникод-поддиапазон, а `next/font/local` не умеет задавать `unicode-range`
для отдельного файла — поэтому latin, latin-ext, cyrillic и cyrillic-ext собраны
в один woff2 на начертание (`src/fonts/inter-400.woff2` и далее).
Пересобрать можно скриптом из истории коммита, если понадобится другой набор
начертаний. Лицензия — `src/fonts/LICENSE`.
